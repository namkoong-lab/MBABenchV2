# ChatGPT web-UI automation for MBABenchV2 — status & decision needed

We have the GUI-automation pipeline running end-to-end on EC2 for both providers (dispatch → cloud browser → upload the case → send the rubric prompts → download the Excel solution → record to Postgres/S3). **Claude (Opus 4.8) works reliably** and produces complete, rubric-compliant workbooks. **ChatGPT (Pro Extended) is inconsistent**, for two reasons. First, driving an automated browser from an AWS cloud IP trips ChatGPT's anti-bot defenses: long responses frequently fail to render ("Content failed to load"), which we've mitigated with auto-recovery that clicks "Try again" on its own. Second, and more fundamental: **Pro Extended is non-deterministic about actually building the file** — given the same prompt that makes Claude produce a real workbook, ChatGPT sometimes just writes *text describing* the model instead of producing a downloadable `.xlsx`, so a share of runs return no usable file. (This is a limitation of the non-agent web UI, not a defect in our code — the pipeline correctly sends prompts, recovers from the load errors, and now flags empty/degraded outputs.)

**What we've tried + the options.** As the cheapest first fix, we've added an explicit instruction to both providers' prompts (kept identical, to preserve comparability) requiring the model to return an actual downloadable `.xlsx` file rather than a text description — we'll validate it on the next run. If that doesn't make ChatGPT reliable, the remaining options are: **(1) ChatGPT Agent mode (Code Interpreter)** — the feature that *deterministically* builds files; we'd deliberately excluded it, but it directly solves the core problem; **(2) the official ChatGPT API** — deterministic file output and the most robust/defensible path for a full run, at the cost of a larger build and per-token pricing; and **(3) cleaner network egress** (residential proxy/NAT) — which would cut the "Content failed to load" errors but does nothing for the file-building non-determinism. Our read: if the prompt tweak doesn't hold up, reliable ChatGPT at scale comes down to **Agent mode vs. the API** — the Pro-Extended web-UI path is inherently unreliable at producing files.

(74)'s `is_instructions_sheet`.

Rubric: "Column widths should not be excessive." Good: "Columns are no wider than their content
requires; several full-width columns fit on screen at once, and long text is wrapped rather than
accommodated by widening the column." Bad: "The model contains excessively wide columns (rule of
thumb: wider than roughly 75-80 characters at the default font), or long text is left unwrapped."
Judge guidance (rubric_9_guidance.yaml): two tests, both required - a column tagged WIDE OUTLIER fails
unless its own content needs the width; any column wider than roughly 75-80 characters at the
default font fails regardless of its neighbours; a helper column sized to its own header label is
not excessive; the case's own brief (the Instructions sheet) is excluded, "including its text
wrapping and column widths".

## Rule as implemented

A workbook fails when any visible column of any worksheet (hidden sheets included) fails Test A or
Test B, or any cell fails Test C. Every threshold is a module constant.

**Units.** A column's width is what Excel's Column Width dialog shows: characters of the workbook's
**Normal font**, `(px - 5) / MDW`. `px` is the column's pixel width at 96 dpi from its stored width
(ECMA-376: `c69.col_px`; a column without `<col>` takes `c69.default_col_px`, strict reading), `MDW`
the Normal font's maximum digit width in whole pixels (7 px for Calibri 11, Aptos Narrow 11 and Arial
10 - every corpus file's Normal font has MDW 7). Stored 150.77734375 is 150.00 characters; Excel
stores UI + 5/MDW.
* Hidden and zero-width columns are skipped (No hidden rows/columns (93) owns them).
* Overlapping `<col>` entries (187 of 374 corpus files, nearly all from GPT-6 tooling, e.g. `F:G 9.0`
  followed by `F:F 44.0`): a later entry - in the reader's order, by `min`, then file order - overrides
  earlier ones on the columns it covers (`paint_cols`). The judge (openpyxl) drops an earlier entry with
  the same `min`, and the core reader's `col_info` returns the default width for columns an earlier range
  covers after a later single entry inside it; no corpus verdict depends on which reading is used
  (`scratch/colwidths70/overlap_modes.py`: no column crosses 75 characters, no outlier group changes).

**Content need** of a column = its widest displayed content, in the same characters:
`text pixels / MDW`, the text measured in the cell's own face, size and weight with c69's glyph
tables (96 dpi, per-glyph rounded advances, the reference model of 69). Characters outside the
tables: accented letters as their base letter, East Asian wide characters 1 em, anything else a
digit (c69's rule).
* Numbers and dates: their displayed text (`numfmt.render` with the cell's resolved format).
  Booleans and errors: their text (`TRUE`, `#N/A`).
* **Unwrapped text: its full width.** Typed line breaks do not break an unwrapped cell (Excel shows
  it on one line).
* **Wrapped text** (`wrapText`, or horizontal justify / distributed): its widest line, **capped at
  the cap** (80): wrapped text can always wrap at the cap.
* Rich text: run by run, each run in its own size and weight (the reader keeps no run face: the
  cell's face).
* Indent adds 3 Normal-font spaces a level (as 69 / 73); rotated text needs its projection on the
  horizontal (stacked text one character).
* Cells in hidden rows (hidden, `ht=0`, no `ht` on a `zeroHeight` sheet) or hidden columns are not
  displayed and need nothing.
* **Merged cells:** covered cells need nothing. The merged content needs the merged width, so every
  column of a horizontal span needs what the span's other visible columns leave
  (`content px - other columns' px`, the "residual"); a one-column (vertical) merge counts in full.
  A merge whose anchor row is hidden shows nothing. Columns touched by a merge are measured again in a
  second pass once the merges are known (`second_pass_sheets`).

**Test A (cap).** A visible column FAILS when it is wider than `WIDTH_CAP_CHARS` (80) **and** more
than `EXCESS_FACTOR` (2) times as wide as its content needs (`width > 80 and width > 2 x need`; toy
wording "> 80 characters with content <= 1/2 of the width"; the exact half passes). Empty columns
with an explicit width over the cap fail (need 0), one mistake per run (e.g. `S!E:XFD`); so do the
columns of a sheet whose own default width (`defaultColWidth` / `baseColWidth`) is over the cap.

**Test B (WIDE OUTLIER).** The judge's tag (`judge/utils/workbook_properties.wide_outlier_tags`,
judge v9) ported on **stored** widths, as the judge computes it:
* inside the sheet's used range (first to last column holding a value or a formula), visible columns
  form runs of equal stored width (`<col>` widths rounded to 2 decimals and compared within 0.01;
  columns without `<col>` take `sheetFormatPr/@defaultColWidth`, else 8.43);
* a run of >= 2 columns, at least `WIDE_OUTLIER_RATIO` (2.5) times as wide as the nearest run of >= 2
  columns that is at least `WIDE_OUTLIER_MIN_NEIGHBOUR` (4) wide **on both sides** (lone columns and
  spacers are skipped when looking for neighbours), and no longer than the longer of the two, is a
  WIDE OUTLIER (kind `judge`). Parity with the judge's own function is tested on 600 random layouts
  (`test_70_judge_port_parity`).
* **Extension** (`OUTLIER_UNEQUAL_GROUPS = True`, kind `ext`): >= 2 adjacent lone columns of unequal
  widths lying between two such neighbour runs, each at least 2.5 times as wide as both neighbours and
  the stretch no longer than the longer neighbour, form a group too. Needed by toy T2 Fail: its AE:AF
  are stored **48.0 and 35.78** (the Overview says both 35.78), two lone columns the exact port never
  compares - with the exact port that Fail toy passes. No corpus verdict depends on it (switches).
* An outlier column FAILS when its content needs less than `OUTLIER_NEED_SHARE` (1/2) of its
  displayed width (toy wording "content needs only 11.67/11.67 characters (< 1/2 of 35)"; the judge
  guidance: fails "unless that column's own content needs the width").

**Test C (long text left unwrapped, `LONG_TEXT_UNWRAPPED = True`).** A text cell - a constant or a
trusted formula result - of at least `LONG_TEXT_MIN_CHARS` (200) characters that is not wrapped, not
in a merge, not shrink-to-fit, unrotated, aligned general / left / right / center, wider than its
column and **spilling into an empty neighbour** on the side its alignment overflows to (general / left:
the right neighbour; right: the left one; center: both) FAILS. A filled neighbour (any value or
formula, even one returning "") stops the spill: that text is cut off, not "accommodated".

**Case brief.** The guidance excludes the case's brief; Patrick's rule grades the whole workbook.
* `EXCLUDE_CASE_BRIEF = False`: the sheet named "Instructions" (`c74.is_instructions_sheet`: trimmed,
  case-insensitive, exactly "Instructions") is graded by Tests A and B like every sheet.
* `LONG_TEXT_SKIP_BRIEF = True`: Test C does not look at it. Every case brief holds 200+ character
  unwrapped paragraphs spilling across empty cells (toy Pass T1 `Instructions!B15`, 213 characters;
  T2 B18, B23, B26, B27, B57; T3 B7, B9): with Test C on the brief all three Pass toys fail. Question 4.

**Values (`needs_values`).** Constants are read from the file. A formula result's value is read
only for cells of the columns being judged (Tests A / B) and for Test C's candidates (unwrapped cells
whose alignment can overflow), and only when trusted; formula results elsewhere are never read. The
recalc pipeline supplies values for every file not saved by Excel. An untrusted value matters only
when its column's measured need is still under the line (Tests A / B), or for an unwrapped cell that
would spill (Test C). If the workbook fails anyway, such cells are listed in `stats.undecided_*`
(`UNTRUSTED_ONLY_IF_VERDICT_NEEDS = True`, as 69 / 73); otherwise the first raises `GradingError`
(no fallback).

**Mistakes.** One per run of adjacent failing columns with the same test(s) per sheet, located at the
columns (`'Solution Model'!H:H`, `'Solution Model'!AE:AF`, `S!E:XFD`), naming each column's width,
its content need and the widest cell, and the test (with the judge's tag line for Test B). Test C: one
per column per sheet, naming the cells. Severity major. Stats: `tests_failed`, `outlier_tags` (the
judge's tag text, `(unequal widths)` for the extension), `outlier_band_columns` (outlier columns whose
need is 50-75 % of the width), `undecided_*`, `brief_fails`, `sheets_with_overlapping_cols`,
`second_pass_sheets`, `per_sheet`, `options`, and **`switches`**: the verdict under each alternative
setting, computed from the same measurements (they never decide): `cap_75`, `outlier_share_0.75`,
`outlier_exact_port`, `test_c_off` / `test_c_on`, `brief_excluded`, `brief_in_test_c`,
`judge_sheet_skip` (Test B skips sheets named like instruction / question / brief / readme, as the
judge's tag does), `cap_80_regardless` / `cap_75_regardless` (Test A fails every column over the cap
whatever its content: the rubric's rule of thumb read literally, as the guidance's second test says)
and `llm_like` (that, plus the brief excluded, Test C off, the 75 % outlier excuse, the exact port and
the judge's sheet skip: how the LLM judge is instructed). `tools/run_corpus.py` keeps these keys.

## Decisions (each behind a constant)

| decision | constant | effect / why |
|---|---|---|
| cap 80 characters | `WIDTH_CAP_CHARS = 80` | the toys' figure; the rubric says "roughly 75-80". `switches.cap_75` reports 75 (sanity counts below) |
| a column over the cap fails only when more than 2x its content | `EXCESS_FACTOR = 2` | the toys' wording ("content <= 1/2 of the width"); the Pass toys' Questions!A (75.57 / 89.71 / 82.57 wide, need 61.1 / 74.3 / 80.0) pass by it. The rubric's "regardless of its neighbours" alone would fail Pass T2 and T3 |
| wrapped text needs at most the cap | (`WIDTH_CAP_CHARS`) | instruction; makes a column of wrapped notes fail only above 160 characters (2 x 80) |
| unwrapped text needs its full width | - | instruction; a 150-character unwrapped note justifies up to 300 characters of width (Test C covers 200+) |
| merged content needs the span: each column the residual | - | a merged title over a wide column justifies it only as far as the other columns of the span do not |
| WIDE OUTLIER = the judge's tag on stored widths, within the used range | `WIDE_OUTLIER_RATIO`, `WIDE_OUTLIER_MIN_NEIGHBOUR`, `WIDE_OUTLIER_EQUAL_TOL`, `JUDGE_DEFAULT_COL_WIDTH` | exact port (600-layout parity test) |
| unequal adjacent lone columns form a group | `OUTLIER_UNEQUAL_GROUPS = True` | toy T2 Fail needs it (AE 48.0, AF 35.78); `switches.outlier_exact_port` reports the exact port |
| an outlier fails below 50 % content | `OUTLIER_NEED_SHARE = 0.5` | toy wording; the earlier prototype excused at 75 % (`switches.outlier_share_0.75`, band list in stats) |
| Test C on, 200 characters | `LONG_TEXT_UNWRAPPED = True`, `LONG_TEXT_MIN_CHARS = 200` | instruction; `switches.test_c_off` |
| the brief is graded by A and B, not by C | `EXCLUDE_CASE_BRIEF = False`, `LONG_TEXT_SKIP_BRIEF = True` | whole-workbook rule vs the guidance; see above and Question 4 |
| hidden columns / rows skipped, hidden sheets graded | - | as 69 / 73; 93 owns hidden columns |
| the judge's sheet-name skip (Instructions / Questions / brief / readme) is NOT ported | (`switches.judge_sheet_skip`) | whole-workbook rule |
| `<col>` without a width = the sheet default; width 0 = hidden | - | the judge (openpyxl) reads a missing width as 13.0 and a zero width as the default; no `<col>` without a width and no unhidden zero width lies inside a used range in the 374 corpus files (`scratch/colwidths70/scan_hidden_runs.py`) |
| hidden runs longer than 2000 columns are hidden | - | the judge treats only runs of <= 2000 hidden columns as hidden; no such run reaches into a used range in the 374 corpus files (same scan) |
| untrusted values only when the verdict needs them | `UNTRUSTED_ONLY_IF_VERDICT_NEEDS = True` | as 69 / 73 |
| conditional-format number formats ignored | - | they change a number's text by a few characters; immaterial at a 2x margin |

## Known limits

* Text widths are c69's 96-dpi glyph model (per-glyph rounding, no hinting); a rich run's face is not
  read (the cell's face is used); unknown faces are measured as Calibri, the narrowest common face (a
  lower need: stricter here, unlike 69).
* Conditional-format number formats are ignored (a few characters at a 2x margin).
* A merge whose anchor row is hidden shows nothing here (Excel may draw it in the visible rows).
* Overflow across a hidden neighbour column is not modelled (the neighbour is column c + 1).
* Center-across-selection text is measured in its own column at full width and is never Test C.
* The unequal-group extension does not join a judge-kind outlier run with adjacent lone wide columns,
  nor two different equal pairs (35, 35, 40, 40): such blocks are not tagged (none in the corpus).
* Test B works in stored widths as the judge does: its 2.5x boundary is unit-sensitive (2.46x stored can
  be 2.54x displayed).
* A LibreOffice conversion of the largest files goes over the guard's 3 GB (attempt 4091, GPT-6 1744);
  production must allow LibreOffice more memory or such files stay ungraded for every value check.
* Test C reads the trusted value of every formula result in a cell whose alignment can overflow (it
  cannot know otherwise whether the result is long text); without a value copy an openpyxl / ChatGPT
  file is "undecided" whenever nothing else fails (the GPT-6 cache run's 120 errors).

## Rule as implemented

**Every cell that displays a negative number must display it in parentheses.** A cell displays a
negative number when

- it holds a numeric value `<= -1e-6` (`NEG_THRESHOLD`): a constant or a formula result (own formula,
  shared-formula child, array / dynamic-array spill / data-table member), on every worksheet, dialog
  sheet and macro sheet of the delivered workbook — hidden sheets, rows and columns included, inherited
  case tabs included, the Questions sheet included (whole workbook, no exemptions);
- a **constant** counts only when its stored type is numeric (`t` absent or `n`): typed text (`"-5"`),
  booleans, errors, ISO dates and empty cells are skipped. A **formula result** is decided from its
  trusted value whatever type the delivered file stores for it (R2-1, 2026-10-04): an openpyxl `t="str"`
  empty cache or a `#NAME?` placeholder whose recalculation copy holds `-5` under General **fails**; a
  genuine text / boolean / error result (`="n/a"`, `=NA()`, `=B1<0`) is not a number and is skipped;
  a needed value that is untrusted (no copy) → GradingError, as for any other untrusted formula;
- and its rendering shows at least one non-zero digit: a negative that rounds to zero on display
  (`-0.3` under `#,##0` → `-0`, `-0.004` under `0.00` → `-0.00`, `(0.00)`) is not judged
  (`ROUNDS_TO_ZERO_COUNTS = False`, question 2). Values in `(-1e-6, 0)` are floating leftovers, not
  negatives (`-1.1e-13` passes; `-1.34e-6` in General shows `-1.34E-06` and fails, as attempt 1985).

What the cell displays is worked out as Excel does (`detchecks.core.numfmt`):

| step | rule |
|---|---|
| number format | the cell's numFmtId: the workbook's own `<numFmt>` first, else the en-US built-in table (5–8 and 37–44 parenthesise; 1–4, 9–13, 48 and General add a minus; 14–22, 45–47 are dates / times) |
| section | 1 section → automatic minus (`#,##0` → `-5`); 2–3 sections → the negative section, no automatic minus (`#,##0;[Red]#,##0` → `1,006`, sign dropped); conditional sections per Excel: `[<0](#,##0);#,##0` → `(5)`, a fallback section after a condition gets **no** minus (`[>=1E11]"big";#,##0` → `1,235`, measured 2026-10-03); 4th section / `@` is text only; a lone `@` shows numbers as General (`-5`); an empty code is General |
| conditional formatting | a CF rule that fires on the cell and carries a number format replaces the cell's format (main and x14 rules; priority order; first firing rule with a format wins; `stopIfTrue` stops). Data bars / icon sets with `showValue="0"` hide the number |

| class | display | examples | verdict | switch |

`[Red]` alone neither helps nor hurts (toy T3: `#,##0;[Red]\(#,##0\)` passes, `#,##0;[Red]#,##0`
fails). Percent formats count (`0.00%;(0.00%)` passes, `0.00%` fails). Non-anchor cells of a merged
range are not displayed and not judged (`SKIP_MERGED_NON_ANCHOR`, counted as `merged_non_anchor`).

**Label literals (R2-3 / R2-4, 2026-10-04).** A quoted or escaped literal of the format that contains a
letter or a digit (`"FY24-25 "`, `" – est."`, `"T-1: "`, `" k-USD"`, `"x)"`, `\k`) is a label: its
letters, digits and dashes are not the number's digits or sign, but its parentheses and other punctuation
still count. The class is taken from a rendering of the section Excel used with the labels' letters,
digits and dashes removed (`strip_label_literals`: `"T-1: "` → `": "`, `"x)"` → `")"`, `\k` → nothing),
and parentheses count only when they **enclose** the number (an unclosed `(` before the first digit, a
`)` after the last digit that closes it); the text shown in the mistake stays the full display. So
`"T-1: "0;"T-1: "(0)` → `T-1: (5)`, `0.0;(0.0)" – est."` → `(5.0) – est.`, `0;"Net ("0")"` → `Net (5)`,
`"("#,##0" bn)"` → `(5 bn)` and the GPT-6 multiples format `0.0\x;\(0.0"x)";\-` → `(1.6x)` pass (parens);
`0;"(est) "0` → `(est) 5` and `0;"(a) "0" (b)"` fail (unsigned: the parentheses do not enclose the
number); `"FY24-25 "#,##0` → `-FY24-25 5` fails (minus); `"FY24-25 "#,##0` on −0.3 is `zero`; `0;"T-1"` is
`text`. Punctuation-only literals (`"-"`, `" -"`, `"("`, `\-`, `\$`) stay whole: `0;(0)"-"` → `(5)-` and
`0;"-"(0)` → `-(5)` are mixed, `0;"Loss: "-0` → `Loss: -5` minus.

### Values are read only where the decision needs them

- A format is **value-free** when every negative under it displays in a passing, value-independent way:
  no conditional sections and the representative negative (`REP_NEG = -1234567.891`) renders as parens,
  date/time, text or blank. Cells under such formats are never read (their trusted negatives are
  counted in stats as `base_<class>`).
- Every other format needs the value: one-section formats, explicit-minus / unsigned / mixed negative
  sections, conditional sections (which section applies depends on the value), scaled formats whose
  representative rounds to zero (`0,,,,`), unreadable formats.
- Constants are always read. A formula result under a value-needing format is read whatever its
  delivered type (`t="n"`, `"str"`, `"e"`, `"b"`; R2-1) — a genuine non-number result is then skipped;
  one with an **untrusted** value
  (core trust policy: openpyxl / XlsxWriter writers, no `<v>`, LibreOffice `#NAME?` / `#VALUE!`) is
  buffered (`MAX_DEFERRED = 50,000` per sheet) and `GradingError` ("needs the value of S!A1 … untrusted …;
  a negative there would not pass (number format 'General' shows a negative as '-1234567.891')") is raised
  at `sheet_end` only if a negative there could still fail: not when the cell is a non-anchor merged cell,
  or a conditional format makes every negative there pass (a `cellIs lessThan 0` rule applying
  `#,##0;(#,##0)`; a hidden-value data bar). A sheet with no merges and no CF rules raises on its first
  buffered cell. Cells beyond the buffer are checked in a second pass.
- Array / data-table ranges whose members are not written in the file (openpyxl legacy arrays, ChatGPT
  dynamic arrays): the members display under the row / column style (else style 0); if that style (with
  the CF rules intersecting the range) could show a negative as a non-pass, their values are needed and
  unavailable → `GradingError` (4091: `Case_001!O8:SP8`, General column style). Same logic as 66.

### Conditional formatting

- Rules evaluated per cell for the actual value `v`: `cellIs` with literal operands (numbers < text <
  logicals; `between` takes min/max), `containsBlanks` / `containsErrors` (false for a number) and their
  negations (true), `containsText` / `beginsWith` / … on the General text of the number (SEARCH wildcards),
  `expression` when it is a literal or compares **the cell itself** with a literal (`B2<0`, `0>B2`;
  relative references shifted from the first range's top-left cell). Data bars / icon sets / colour scales
  apply to every number. Everything else (`top10`, `aboveAverage`, `duplicateValues`, `timePeriod`,
  expressions reading other cells, `ABS(...)` wrappers) is **unknown**: both outcomes are tried (up to
  `MAX_UNKNOWN_RULES = 8` per cell). If the outcomes disagree on the verdict → `GradingError`; if they
  agree the verdict stands.
- For an **unknown negative** (untrusted / missing values; second-pass need) the same evaluator runs with
  the sentinel `NEG`: a rule fires for every negative (`lessThan X` with `X >= 0`, `notEqual 0`,
  `lessThan "text"`, `B2<0`), for none (`greaterThan X` with `X >= 0`, `equal 0`, `between 0 100`) or
  unknown (`lessThan -100`: only some negatives).
- **Second pass** (`request_second_pass`), only for a sheet with a CF rule whose number format is not
  value-free (a minus / unsigned / conditional format, or unreadable) and that can fire on a negative:
  cells under value-free base formats inside those rules' ranges are re-streamed; a value is read only
  if some CF outcome for a negative there would fail.

### Mistakes

One mistake per rectangle of failing negatives sharing the same format, class and CF origin
(`group_cells`: row runs, then stacked), per sheet in tab order; the rectangle's first cell gives the
example text. Location `'Sheet'!A1:C3`; description e.g. `4 negative value(s) G15:J15 display with a
minus sign, e.g. '-21795' (number format 'General'), not in parentheses.`; unsigned: `display without a
sign or parentheses, e.g. '1,006' (number format '#,##0;[Red]#,##0')`; mixed: `display a minus sign as
well as parentheses, e.g. '-(5)'`; CF: `(conditional-format number format '0.0')`; `(hidden sheet)` where
it applies. Capped at 25; totals in `stats.n_mistakes` (rectangles), `stats.negative_cells_failing`
(cells) and the summary.

Stats: `negative_cells_failing`, `negative_cells_by_display` (`judged_<class>` for negatives decided
with their value, `base_<class>` for trusted negatives under value-free formats, `merged_non_anchor`),
`formula_values_read`, `untrusted_values_not_needed`, `array_members_not_in_file`, `cf_rule_sheets`,
`cf_second_pass_sheets`, `deferred_second_pass_sheets`, `hidden_sheets_with_failures`, `examples` (8),
`policy`.

### No guess (GradingError)

- a formula value the decision needs is untrusted (decided at the sheet's end, see above);
- an array / data-table range has members missing from the file whose style could show a negative as a
  non-pass, or is not anchored at its top-left cell;
- the number format of a judged negative cannot be read (numFmtId with no `<numFmt>` and no built-in
  meaning) — a text, positive or zero cell under such a style is fine;
- Excel's display is not verified by the format engine (`certain=False`: a negative under a format whose
  only condition sits on the second section; `#####` when no section applies);
- CF rules decide the verdict and cannot be evaluated, or more than 8 unknown rules cover a cell;
- a CF rule's number format cannot be read and the rule may fire.

## Known limits

- Column width is not modelled: a negative too wide for its column (`#####`) is judged by its format.
- Formats are classified as value-free from one representative negative (`-1234567.891`): a format that
  parenthesises only some magnitudes (impossible without conditions) does not exist, but a scaled format
  whose representative rounds to zero (`0,,,,`) is read like a minus format (conservative, never a false
  verdict).
- A literal negative section containing a dash (`#,##0;\-`) shows a dash with no number and passes as
  text (question 3); none in the corpus except the near-zero `"-"` section of 1542.
- Core `numfmt.Rendered.parens` / `.minus` read literal digits as the number's: `"FY24-25 "(#,##0)` on −5
  gives `parens=False` and `"T-1: "(0)` `minus=True` (R2-4). This check uses neither flag any more (it
  classifies the label-stripped rendering with its own enclosing-parentheses test), so its verdict is
  right; the core flags themselves are left to the core owner.
- Whether a dash inside a label literal that touches the number is a sign cannot be told from the text;
  the label rule says no: `"Loss -"0` → `Loss -5` is `unsigned` (fails anyway) and `0;"Loss -"(0)` →
  `Loss -(5)` passes as parens. None in the corpus.
- Array members missing from the file: styles per range, as in 66; values never read from a copy.
- CF expressions are evaluated only in the forms listed; `ABS(B2)<0` style wrappers are unknown (they
  raise only when the verdict depends on them). None in the corpus.
- Table styles / pivot formats do not set number formats here.
- A sheet with untrusted needed values is streamed to its end before the check raises.

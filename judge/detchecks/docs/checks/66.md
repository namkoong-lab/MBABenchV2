## Rule as implemented

**Every cell holding a numeric value of exactly 0 must display a dash.** This covers constants and
formula results (own formula, shared-formula children, array / spill / data-table members) on
every worksheet, dialog sheet and macro sheet of the delivered workbook. Hidden sheets, hidden
rows and hidden columns count like any other (whole workbook). **Patrick's ruling 2026-10-02:
the plain rule applies** — period counters, index cells and 1/0 switches showing 0 fail too; there
is no label, lexicon or "structural" exemption, and no starting-file diff.

What the cell displays is worked out as Excel does (rendering by `detchecks.core.numfmt`):

| step | rule |
|---|---|
| number format | the cell's numFmtId: the workbook's own `<numFmt>` first, else the en-US built-in table (41–44 have a dash zero section, 37–40 do not — 66 T3 trap) |
| section for 0 | 3+ sections: the 3rd; 1–2 sections: the 1st (`#,##0;(#,##0)` shows `0`); conditional sections evaluated (`[=0]"-";#,##0` dash, `[>=1E11]"big";#,##0` → `0`); a lone `@` shows General |
| conditional formatting | a CF rule that fires on the cell and carries a number format replaces the cell's format (main and x14 rules; priority order; first firing rule with a format wins; `stopIfTrue` stops). Data bars / icon sets with `showValue="0"` hide the number (class `hidden`) |
| sheet option | `showZeros="0"` on the sheet's view (window 0): under General and single- / two-section formats a zero that would show a digit or text is hidden; a format with an **explicit zero section** (three numeric sections) still prints that section (`0.00;-0.00;0.00` → `0.00` fails, `0;-0;"nil"` → `nil` fails, `#,##0;(#,##0);"-"` → `-` passes). Measured in Excel 2026-10-03 for **base formats** only (two-section formats not measured; a base format with conditional sections is unverified). A number format applied by a **conditional format** on such a sheet is unmeasured: a digit / text zero there is `uncertain` and raises when it decides (66-S2; a CF dash / blank passes either way). `numfmt.zero_hidden_by_show_zeros_off`, `c66._cf_hide` |

Outcome per zero cell:

| display | examples | verdict | switch |
|---|---|---|---|
| dash | only dash characters (`-`, en/em dash, minus sign) once spaces / padding, currency symbols (Unicode Sc and `[$xxx-nnn]` tags), brackets and the format's **own number decorations** are removed: `-` `\-` `"-"`, `--`, `(-)`, accounting ` -   ` / ` $-   ` / ` CHF -   ` / ` -   € `, a `* -` or `*-` fill; since 66-S1 also a dash beside a quoted currency code or unit label that the positive section prints around every number (`c66.decorations`: its quoted / escaped literals and `%`, longest first, never a literal holding a digit or a dash, nothing from a literal-only positive section): Excel's sv-SE ` -   kr`, de-CH `CHF -`, pt-BR `R$ -`, en-ZA `R -`, `zł`, `Kč`, `USD -`, and `-x` under `0.0"x";(0.0"x");"-x"`, `-%` under `0.0%;(0.0%);"-"%`, `- bps` | pass | `STRICT_DASH = True` |
| digit | `0`, `0.00`, `0%`, `0.0%`, `$0.00`, `0.00E+00`, General `0`, a number under `@` | **FAIL** | |
| visible non-dash text | `0;-0;"nil"` → `nil`; `n-a`, `zero-rated`, `N/A - nil`, `—none—`, `"nil"*-`, `-/-`; a label the numbers do not carry: `-x` under `0;-0;"-x"`, `USD -` under `0;-0;"USD -"`, `n-a` under `0"na";-0"na";"n-a"`; `#####` | **FAIL** | `NON_DASH_TEXT_FAILS = True` (with `STRICT_DASH`; before the first review a text merely containing a dash passed; before the second review a dash beside a quoted currency code or unit failed while the identical display via `€` / `[$CHF]` passed) |
| blank (by the format) | `;;;`, an empty zero section (`#,##0;(#,##0);`, `0;-0;;@`), `#,###` | pass (check 94 fails a format blank) | `BLANK_ZERO_PASSES = True` |
| hidden (not by the format) | `showZeros="0"` sheet under a format without a zero section; a data bar / icon set with `showValue="0"` | pass — **check 94 does NOT charge these** (it records them only), so as built neither check fails them; question 2 | `HIDDEN_ZERO_PASSES = True` |
| date / time / elapsed format | `1/0/1900`, `0-Jan-00`, `0:00`, `[h]:mm` → `0:00`, `h:mm:ss.000` | not judged (a date/time, not a number) | `DATE_TIME_IN_SCOPE = False` |
| uncertain | Excel's display is unmeasured: a digit / text zero under a conditional format's number format on a `showZeros="0"` sheet (66-S2); a section mixing digit placeholders with unquoted date-time letters — `0 bps`, `0 days`, `0 yrs`, `#,##0 d` (unquoted unit letters the engine would read as date codes; Excel's dialog rejects them, openpyxl writes them; 66-S3 — since 2026-10-04 the format engine marks such codes unverified, `numfmt.mixed_date_letters`, so their renders are `certain=False`); a base format with conditional sections on a `showZeros="0"` sheet; any other engine render with `certain=False` | **GradingError** (no guess) | |

Never judged (not numeric zeros): booleans (`FALSE`, also formula results — 66 T1/T2 trap: tens of
thousands of `t="b"` flag cells), text `"0"` (shared, inline or a formula's string result), error
values, empty cells, formulas returning `""`, ISO-date (`t="d"`) cells.

Not zeros: a value that is not exactly 0 is not judged even if it displays as zero
(a `2.33E-10` / `3.6e-12` residue under `#,##0.00` shows `0.00`; `0.0004` under `0` shows `0`)
— `DISPLAYED_ZERO_COUNTS = False`. `-0` is a zero.

Values hidden under a merged range (any cell of the merge other than its top-left one) are not
displayed and not judged (`SKIP_MERGED_NON_ANCHOR = True`; counted in stats as
`merged_non_anchor`). The merge's top-left cell is judged. Lookup: a per-column index of the
merges sorted by first row, one bisect per cell (review fix 66-R4: was a scan of every merge in
the column, quadratic; 20k one-row merges 5.3 s → 0.24 s, 40k 20.5 s → 0.49 s, 200k 2.7 s;
overlapping merges, invalid in Excel, fall back to a scan).

### Values are read only where the decision needs them

- Constants are always read.
- A formula result is read **only when its formatting on this sheet would show a zero as a
  non-pass**: its own format shows 0 as a digit / text / unverified (on a `showZeros="0"` sheet
  such a zero is hidden, so no read), or (second pass, below) a conditional format on it could.
- A formula under a dash, blank or date/time format is not read at all (its value cannot
  change the verdict). For the stats only, its value is counted when it is trusted
  (`base_dash`, `base_blank`, `base_hidden`, `base_datetime`); no read there can raise.
- An **untrusted** value (core trust policy) is not refused at once (review fix 66-R1): the
  cell is buffered (`MAX_DEFERRED = 50,000` per sheet) until the sheet tail is known, and
  `GradingError` ("needs the value of S!A1 ... untrusted ...; a zero there would not pass ...")
  is raised at `sheet_end` only if a zero there would still fail: not when the cell is a
  non-anchor merged cell, or a conditional format makes every zero there pass (e.g. `=0` → `"-"`,
  a hidden-value data bar). A sheet with no merges and no CF rules raises on its first buffered
  cell at once. Cells beyond the buffer are checked the same way in a second pass (same
  predicate, same stream order). Stats: `untrusted_values_not_needed`,
  `deferred_second_pass_sheets`.

Consequence of the core trust policy (not changed here): in openpyxl- and XlsxWriter-labelled
files without a recalculation copy, a formula under a digit-showing format (typically General)
raises `GradingError` at the end of its sheet unless the tail rescues it (no corpus file is
rescued today). Constants and formulas under dash formats are graded normally. **Patrick
2026-10-04 ("match v12"):** in the pipeline's LibreOffice copy a `#NAME?` / `#VALUE!` value is
vetted by the gap scan (`ValueSource(errors_vetted=True)`, docs/reader.md) and the check then sees
an error, not a number, and skips the cell — no loud error for those files; only a manually
supplied `value_path` keeps the loud error (former question 11, now decided).

### Array members missing from the file (sanity finding, fixed 2026-10-03)

Some writers (openpyxl legacy array formulas `<f t="array" ref="O8:SP8">`, ChatGPT dynamic
arrays with `cm=`) write only the anchor cell of a multi-cell array / data-table range; the
members have no `<c>`, so the cell stream never shows them, yet Excel computes and displays
them under the row style (`customFormat="1"`) or else the column style or else style 0. The
check counts the members it sees per range (anchor ref → members seen) and, at `sheet_end`, for
each range with missing members works out the styles those cells get (the anchor's own row /
column is left out for one-row / one-column ranges). If any such style (with the CF rules that
intersect the range, evaluated without a cell position) could show a zero as a non-pass, their
values are needed and not available — the core streams only written cells and does not read a
value copy for missing ones — so it raises `GradingError` ("... is an array formula range ...
with N member cell(s) not written in the file ..."). A dash / blank / date style, or a
`showZeros="0"` sheet, needs no value. Stats: `array_members_not_in_file`. Corpus: 2 files have
such ranges (4091 attempt, 2621 GPT-6); 2621 already raised (no cached values); **4091 with its
LibreOffice copy changes from pass to GradingError** (General column style; its pass was right
only because the copy's values happen to be non-zero, which the check cannot see).

### Conditional formatting

- First pass: cells whose base format shows 0 as a non-pass are read; their zeros are buffered
  and decided in `sheet_end` once the CF rules (in the sheet tail) are known.
- CF rules evaluated per cell for a number `v` with the shared evaluator `checks/_cfeval.py`
  (2026-10-05): `cellIs` with literal **or formula** operands (`$B$1`, `-Assumptions!$F$122`, a defined
  name; numbers < text < logicals; `between` takes min/max), `containsBlanks` / `containsErrors` (false
  for a number), their negations (true), `containsText` / `beginsWith` / ... (on the General text of the
  number, SEARCH wildcards), and `expression` rules: comparisons, arithmetic, `&`, LEFT RIGHT MID LEN
  UPPER LOWER TRIM VALUE TEXT EXACT SEARCH FIND, ISNUMBER ISTEXT ISBLANK ISERROR (and ISERR ISNA
  ISLOGICAL ISNONTEXT), AND OR NOT IF IFERROR, ABS ROUND ROUNDUP ROUNDDOWN INT TRUNC MOD ISEVEN ISODD ROW
  COLUMN; references to the cell itself, to other cells of the sheet and to other sheets (absolute and
  relative, shifted from the first range's top-left cell to each cell), read through the grading's
  value source (`core/lookup.py`). Data bars / icon sets / colour scales apply to every number in range.
- **Patrick 2026-10-05 - "CONDITIONAL FORMATS never stop a grading":** a rule the evaluator cannot
  evaluate (`top10`, `aboveAverage`, `duplicateValues`, `timePeriod`, COUNTIF / SUM / YEAR ..., a range
  operand, a referenced formula whose value is untrusted, an unreadable dxf number format) is taken as
  **OFF**: the cell is graded by its own formatting as if the rule were off. A conditional-format number
  format whose display is not verified (a digit / text zero under it on a `showZeros="0"` sheet, a
  render the engine marks `certain=False`) gives way to the cell's own format the same way. Both never
  raise. Every such assumption is recorded in `stats.cf_assumptions` (`cells` graded under one,
  `decisive_cells` where the assumption decides the cell's verdict, `examples`, `unevaluable_rules` and
  their examples). A cell whose base format passes but which an unevaluable rule could fail is read (when
  its value is trusted) so that the assumption is recorded.
- **Second pass** (`request_second_pass`), only for a sheet with a CF rule whose number format
  shows 0 as a non-pass on that sheet (on a `showZeros="0"` sheet only an unverified render
  counts) and that can fire on 0: cells under a dash/blank/date base format inside those rules'
  ranges are re-streamed; a cell's value is read only if some CF outcome for 0 would fail it. The
  same second pass also checks untrusted cells beyond the `MAX_DEFERRED` buffer (above).

### Mistakes

- One mistake per rectangle of failing zeros sharing the same displayed text and format
  (`add_cell_mistakes`: row runs, then stacked), per sheet in tab order, groups ordered by their

  (number format '#,##0.00') instead of a dash.`; a CF format says
  `(conditional-format number format '0.00')`; `(hidden sheet)` where it applies. Only when a

  (cells) and in the summary.

### No guess (GradingError)

- a formula value the decision needs is untrusted (above; decided at the sheet's end);
- an array / data-table range has members missing from the file whose style could show a zero
  as a non-pass (above), or such a range is not anchored at its top-left cell;
- the number format of a numeric zero cannot be read (numFmtId with no `<numFmt>` and no built-in
  meaning, e.g. 23–26, 63–66) — a text or non-zero cell under such a style is fine;
- Excel's display of the zero is not verified by the format engine (`certain=False`: a value no
  conditional section matches; a section mixing digit placeholders with unquoted date-time letters,
  `0 bps`, `0 days`, `#,##0 d`: 66-S3, `numfmt.mixed_date_letters`; `h:mm:ss.000` is a genuine time
  format), or by this check: a base format with conditional sections on a `showZeros="0"` sheet
  (66-S2).
Since 2026-10-05 nothing about a conditional format raises (Patrick): a conditional format's digit /
text number format on a `showZeros="0"` sheet, a CF rule that cannot be evaluated, more than 8 such
rules on a cell and a CF rule whose number format cannot be read all give way to the cell's own format
(recorded in `stats.cf_assumptions`).

## Known limits

- Column width is not modelled: a zero is never `#####` for width reasons (a dash or `0` always fits).
- `showZeros="0"`: since 2026-10-03 Excel's measured behaviour (a zero section is printed, General
  and single-section formats are blank). Two-section formats (`#,##0;(#,##0)`) are read as
  blank (no zero section of their own; not measured). A conditional format's number format on
  such a sheet is unmeasured and raises when a digit / text zero depends on it (66-S2; question
  12). No corpus file has a `showZeros="0"` sheet.
- Number decorations (66-S1) are taken from the section a positive value uses; a format that
  decorates only its negative section is not credited (its zero would be text), and a format
  whose positive literal happens to equal the zero section's label (`0"na";-0"na";"n-a"` stays
  text, `0"nil";-0"nil";"nil"*-` would pass) is judged by substring removal — both are contrived,
  none is in the corpus (0 of 392 codes change class).
- Mixed date / digit codes (66-S3) are caught by the format engine since 2026-10-04
  (`numfmt.mixed_date_letters`: every number rendered under such a code is `certain=False`, for
  every check); the check's own `mixed_date_section` is gone. The core rule is a little wider than
  the check's was: it also covers a number section with an era / Buddhist-year letter (`0 b`, `0.0E`,
  formerly read as a number with a literal letter), `General` or `@` beside date letters, and digits
  after a `.` that does not follow a seconds code (`d.00`). No corpus or toy code is affected.
- Array members missing from the file: their styles are worked out per range, not per cell (the
  anchor's row / column is left out only for one-row / one-column ranges; members that ARE written
  do not narrow the set), so a mixed range can raise where an exact per-cell view would not; a
  missing member under a non-anchor merge is not skipped. Both err towards GradingError, never a
  false verdict. Values of missing members are never read, even when a value copy has them (the
  core streams written cells only).
- A sheet with untrusted needed values is streamed to its end before the check raises (the tail
  may rescue the cells), so an ungradable file costs one full sheet read instead of stopping at
  the first cell.
- Table styles and pivot-table formats do not set number formats here (they are applied to the
  cells' own `s` by Excel); a pivot's in-memory number format that is not written to the cell
  would be missed.
- CF expressions are only evaluated in the forms listed above; other forms raise only when the
  verdict depends on them.
- Merged-range detection: a zero under a merge but not its top-left cell is skipped even if Excel
  would show it after unmerging (it is not displayed in the delivered file).

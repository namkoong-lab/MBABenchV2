## Rule as implemented

**Patrick's ruling 2026-10-02: STRICT A1.** The check fails on every sheet whose cursor (active cell) is not A1 when the workbook opens. The rubric's "(or the sheet's designated home cell)" and the frozen-pane-corner exception are dropped. A frozen sheet whose cursor sits on the first unfrozen cell (A4, F4, A5), where Ctrl+Home lands, fails too.

| point | decision |
|---|---|
| which view | the sheet's view for workbook window 0, else its first view (`SheetHead.view`); views of further windows are listed in stats only |
| which selection | the `<selection>` of the view's **active pane** (`<pane activePane>`; `topLeft` when there is no pane; a selection without `pane=` is topLeft). **Not** the first `<selection>`: toys T2 ('Utilities': first selection topLeft I276, active bottomLeft A4) and T3 ('Solution Model': first selection topRight F1, active bottomRight F4/F5) set this trap |
| no sheetView, or no selection on a view without panes | cursor A1 (Excel's default: Excel omits an A1 selection) |
| a view with panes whose **active pane (not topLeft) has no selection** (another pane may have one) | the cursor is the **active pane's top-left cell** (the pane's `topLeftCell`, else the frozen corner; `ACTIVE_PANE_WITHOUT_SELECTION = "pane_top_left"`). Measured in Excel by Patrick 2026-10-03 (attempt 1408: frozen sheets whose only selection is A1 in the topLeft pane open on D7 / D7 / F10, the first scrolling cell), so strict A1 **fails** these sheets. Listed in `stats.active_pane_without_selection` (sheet → that cell). The measurement had the scrolling pane **at** the frozen corner (pane `topLeftCell` = corner). When the pane is parked beyond the corner (GPT-6 1353: `topLeftCell="R6"`, corner F6) the pane's `topLeftCell` stays the primary reading (location `'Statements'!R6`) and the corner is a second candidate, named in the mistake ("R6 (or F6) ... Excel was measured only with the pane at the corner"); both fail strict A1 (re-review 2026-10-04, `62-scrolled-pane-location`). A view without panes with no selection is A1. The old readings stay available as switches (`"A1"`, `"unverified"`) |
| a view with panes whose **active pane is topLeft** and has no topLeft selection | A1 when the view's `topLeftCell` is A1 (GPT-6 1750 / 1762, 15 sheets: openpyxl files with `activePane="topLeft"` set by the agent). When the view is **scrolled** (`sheetView topLeftCell="C1"`) the candidates are A1 (Excel's default for a missing selection) and C1 (the active pane's top-left cell, the 1408 reading applied to the topLeft pane): not measured, so the sheet is undecidable (re-review 2026-10-04, `62-topleft-active-ignores-view-scroll`; 0 corpus sheets). Under the `"A1"` switch it is A1 |
| a view **without `<pane>`** whose selections carry a pane label other than topLeft | stray labels: openpyxl keeps them after `ws.freeze_panes = None` (`<selection pane="bottomRight" activeCell="D10"/>` with no `<pane>`). Excel's resolution is not measured, so every stray selection's cell is a candidate next to the topLeft reading (default A1): all A1 → pass, none A1 → fail at the topLeft reading, mixed → undecidable (re-review 2026-10-04, `62-stray-pane-label-silent-a1`; before, the stray selection was ignored and the sheet passed as A1). Listed in `stats.selections_labelled_without_pane`. 0 corpus sheets: all 562 pane-less selections with a `pane=` label say `topLeft` |
| selection without activeCell | A1 when its sqref is absent or starts at A1 (XlsxWriter writes `<selection pane="bottomLeft"/>` for an A1 cursor) |
| selection without sqref | the sqref is the schema default `"A1"` (ECMA-376 CT_Selection). So `<selection activeCell="D10"/>` is the same shape as `<selection activeCell="D10" sqref="A1"/>` (openpyxl's shape): an activeCell outside its selection, candidates D10 and A1 (review fix 2026-10-03, finding `62-default-sqref-inconsistent`; before, the first failed at D10 and the second raised) |
| range selected with activeCell A1 (A1:D10) | the cursor is A1: pass |
| unverified shapes | every plausible cursor is kept as a candidate: several selections for the active pane (all of them); a selection without activeCell whose sqref starts elsewhere (A1 and the sqref's first cell); an activeCell outside its own sqref, explicit or default (the activeCell and the sqref's first cell); the three shapes above (scrolled pane without selection, scrolled view with an active topLeft pane without selection, stray pane labels). **All candidates A1 → the sheet passes; none A1 → it fails (location = the primary reading, the others named in the text); mixed → the sheet is undecidable** (see "No guess") |
| sheets counted | worksheets, dialog sheets and macro sheets, **hidden and very hidden ones included** (`INCLUDE_HIDDEN_SHEETS = True`, whole workbook) |
| chart sheets | no cell cursor (a chartsheet view has no `<selection>`): listed in `stats.excluded_sheets`, never failed |
| scroll position | not judged (`CHECK_SCROLL = False`). A view that opens scrolled away from A1 (sheetView `topLeftCell` ≠ A1, or a frozen sheet whose scrolling pane does not start at the frozen corner) is listed in `stats.scrolled_views`. With `CHECK_SCROLL = True` a sheet with its cursor on A1 but scrolled away fails |

Only sheet heads are read; sheet data is skipped at byte level.

### Mistakes

- There is one mistake per failing sheet, in tab order. The location is `'Sheet'!<cursor cell>`, for example `'Solution Model'!K37`. Severity is minor.
- The description names:
  - the cursor cell (plus the other candidates, if any);
  - the active pane it was read from;
  - the selected range, when it is wider than the cursor;
  - "this is the frozen-pane corner, where Ctrl+Home lands; the rule is strict A1, so select A1 itself", for frozen-corner cursors;
  - "(hidden sheet)", where it applies.
- The summary lists the failing sheets with their cursors.

### No guess: an undecidable sheet raises only when it decides

A sheet is **undecidable** when:
- the selection that decides has an activeCell or sqref that is not a cell reference or range on the grid;
- `activePane` is not one of the four pane names;
- its candidates are mixed (above).

**Several selections for the active pane are decided since 2026-10-06, not undecidable**: Excel opens on the **last** one stored (Patrick, in Excel: attempt 2379 'Income Statement' / 'Budget - Income Statement' store bottomRight `A1` then `B9` and open on B9; attempt 2402 'Balance Sheet' stores `A1` then `A4` and opens on A4; docs/excel_measurements.md item 11). The earlier selections are noted in `stats.cursors.<sheet>.notes`, not candidates. The shape is openpyxl's: `ws.freeze_panes` appends the pane's own selection after one the agent had set. Before, such a sheet was undecidable (and raised when no other sheet failed for certain): attempts 2379, 2402, 3390 and 3505 could not be graded by judge v13; under the measured rule all four fail (cursor on the frozen corner), and 3505's 'P&L Budget – GL Detail' (C1 then A1) passes. Tests `test_62_unverified_shapes` (c_dup2 fails at C5, c_dup3 with the order reversed passes).

An undecidable sheet never gets a mistake. If another counted sheet fails for certain, the verdict is fail; the undecidable sheets are listed in `stats.undecidable_sheets` and named in the summary ("the verdict does not depend on it"). If no sheet fails for certain, the unknown cursor decides, so the check raises GradingError naming every undecidable sheet. Review fix 2026-10-03 (finding `62-raises-although-already-failing`): before, any undecidable sheet raised straight away.

An unreadable sheet part raises in the engine.

## Edge-case decisions

- **Hidden sheets count.** Rubric: "on every sheet". House Standards: "cursor at A1 on every sheet". Reader ground rule: "whole workbook". The toy Overview's wording ("the rule counts every visible sheet") is not tested by any toy; see Q1.
- **Frozen-corner cursors fail** (ruling). The description says so explicitly, because Ctrl+Home lands on the corner rather than on A1 on a frozen sheet.
- **Selection shapes in the 71 corpus attempts** (census of the prototype's view dump):
  - 21 sheets have a frozen pane whose active pane has no selection. This is A1 by rule.
  - 22 sheets have a selection without activeCell and without sqref (A1).
  - 5 sheets have duplicate active-pane selections. All are A1, so the decision is the same either way.
  - None has an activeCell outside its sqref or a sqref without activeCell.
  - None is scrolled.
  - 23 sheets have a cursor that is not A1. Most are frozen-corner cursors (1927, 932, 3822, 4012, 4091), plus the inherited case-tab cursors of 2285, 2061 and 2117, and 3156 Balance Sheet A4 (range A4:G4).

## Known limits

- Excel's resolution of the unverified selection shapes (duplicate active-pane selections, sqref without activeCell, activeCell outside its sqref, stray pane labels, a scrolled view with an active topLeft pane without selection) is not modelled; they raise only when the decision depends on them.
- An active pane (not topLeft) without a selection is read as the pane's top-left cell (measured, 1408); when that pane is parked beyond the frozen corner the corner is a second candidate (not measured; both fail). The sheets where it matters are in `stats.active_pane_without_selection`.
- **Unmeasured and load-bearing (question 5):** openpyxl's default frozen-pane shape stores the A1 selection *for the active non-topLeft pane* (attempt 1272 'FCF': `<pane xSplit="5" ySplit="10" topLeftCell="F11" activePane="bottomRight"/>` + `<selection pane="bottomRight" activeCell="A1" sqref="A1"/>`). The check takes the stored A1 at face value and passes; 89 passing files (68 openpyxl, 14 LibreOffice, 4 Excel Online, 3 unknown; 805 sheets) rest on it. The 1408 measurement covered the sibling shape (A1 stored for topLeft) only. If Excel moves such a cursor to the pane corner, ~85 files flip to fail. Not changed here: a flip of that size is a ruling, not a review fix.
- The cursor of a second workbook window is not judged.

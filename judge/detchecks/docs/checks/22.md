## Rule as implemented

**FAIL if any cell on any sheet of the delivered workbook DISPLAYS an Excel error value** - #REF!,
#N/A, #DIV/0!, #VALUE!, #NUM!, #NULL!, #NAME?, #SPILL!, #CALC!, #GETTING_DATA (and the other rich
error types: #CONNECT!, #BLOCKED!, #FIELD!, ...) - per its **trusted value**:

| file | value source |
|---|---|
| saved by Excel | the file's own cache (Excel's display) |
| anything else | the recalculation pipeline: LibreOffice copy; rerouted to a real-Excel copy when LibreOffice has gaps (functions it lacks, spill references, LAMBDA names, array-evaluation differences); `GradingError` when Excel is needed and not allowed / not available |

Every formula cell's value is read (own formulas, shared children, array / spill / data-table
members). An untrusted or missing value → `GradingError` (no fallback): openpyxl caches without the
pipeline, a formula with no `<v>` in an Excel file, a cell the copy lacks.

| counts | why |
|---|---|
| formula result that is an error | displayed |
| typed error constant (`t="e"`, no formula; a pasted `#N/A`) | displayed |
| deliberate `=NA()` | the rubric has no exception |
| broken reference `=E79-#REF!` (toy T4) | displays #REF! |
| misspelled function `CONUTIFS` (toy T6) | displays #NAME? |
| blocked spill (toy T7): cached as `t="e"` `#VALUE!` with `vm` → decoded through `xl/metadata.xml` → `xl/richData/rdrichvalue.xml` (`_error.errorType` 8 = #SPILL!, 13 = #CALC!) when the value is the file's own cache; from a recalc copy it is reported as `#VALUE!` (still an error) | Excel shows #SPILL! |
| implicit intersection (toy T5): a plain (non-array) formula using a multi-cell range as a single value from a cell outside the range → #VALUE! in Excel though the cache / LibreOffice show a number. `judge/utils/implicit_intersection.py` (loaded read-only from its file; only what it flags is flagged), run on every plain formula whatever the value source, after a cheap prefilter (`may_intersect_outside`: some A1:B2 range in the text does not contain the cell's row / column) | Excel ground truth after recalculation |
| each member of an erroring array / spill range | each cell displays the error (grouped into one rectangle, described by the anchor's formula) |
| errors on hidden sheets, hidden rows / columns, under `;;;` or white font, in zero-width columns | they ARE error values; "any cell on any sheet"; concealment is check 94's domain |

| does not count | why |
|---|---|
| errors caught by IFERROR / IFNA / ISERROR / ISNA ... | the cell displays the fallback (toy T3) |
| text that reads `#N/A` (string constant or a formula's string result) | not an error value |
| circular references with iteration off | check 100's domain; the value source decides what Excel shows (0 / last value). Caveat: a LibreOffice copy exports Err:522 as #VALUE! (docs/recalc.md Q1) |
| a dynamic-array formula (`t="array"`, `cm="1"`) | array-evaluated; no implicit intersection (T5 Pass) |

Mistakes: one per (sheet, error code, kind) rectangle: `"4 cell(s) G18:G21 display #DIV/0! (e.g.
G18: =$D18/$D$21)."`; typed constants `"display the typed error value #N/A"`; implicit
intersection `"display #VALUE! in Excel (implicit intersection: $I$8:$R$8 used as a single value from
outside it; the stored value is a number because the writer did not intersect)"`; `[hidden sheet]`
appended on hidden sheets. Stats: `formula_cells`, `error_cells`, `error_cells_by_code`,
`typed_error_constants`, `implicit_intersection_cells`, `implicit_intersection_checked`,
`sheets_with_errors`, `hidden_sheets_with_errors`, `examples`, and `values` (pipeline provenance).

## Questions for Patrick

1. **Implicit intersection on Excel-saved files without `fullCalcOnLoad`**: the detector is applied
   whatever the value source, so a stale-looking cache is overruled by the detector. If Excel's
   cache shows a number for a flagged formula, the detector (probed on 155 formulas) would be
   wrong - no such case in the toys. Keep "always apply" (implemented) or trust an Excel cache
   over the detector?
2. **Unprefixed future functions** (`xlookup(` without `_xlfn.` written by a non-Excel tool, corpus
   2121): LibreOffice 25.8 computes them; Excel may show #NAME?. Measure once with the Excel path;
   if #NAME?, add a static rule (then 22 fails such files whatever the value source).
3. **Rich errors from a recalc copy**: reported as `#VALUE!` (the copy's `vm` is not followed). Fine
   for the verdict; wording only.
4. **Formula cells without any cached value in an Excel-saved file** raise (untrusted). Excel always
   writes `<v>` for computed cells, so this should not occur; confirm raise over "recalculate".
5. **Circular references through a LibreOffice copy** (Err:522 → #VALUE!): see docs/recalc.md Q1.

## Judge v15 (Patrick 2026-10-28): live, gap cells undecided, unprefixed functions genuine

- **Live** (`C22.live = True`, `det_checks.live` in `project_configs.yaml`). Recorded only under
  v13/v14 because, with Excel recalculation off, the cells LibreOffice cannot compute showed as errors.
- **Per attempt**: any error in a NON-gap cell (typed constant, implicit intersection, a genuine
  LibreOffice error, an Excel-cached error) → **fail** by code, the gap cells listed in stats beside
  it (`gap_error_cells`, `gap_error_examples`, `gap_sheets`), never as mistakes; no error cell →
  **pass** by code; the only cells showing errors are gap cells → **undecided** (`checks/base.py`): the
  LLM judge decides this attempt, told in `llm_note` which cells are gaps (sheet!ref, the formula, the
  function LibreOffice lacks) and that every other cell was checked by code and is error-free.
  `stats.decided_by` says `code` or `llm`. Dependents of a gap cell (`=B1*2` under a LAMBDA cell) are
  gaps too (`classify_lo_error` on a `#NAME?` with only valid functions). A file saved by Excel, or
  recalculated by Excel (`RecalcPolicy.excel_allowed`, kept OFF), has no gap cells.
- The full gap set reaches the check through `Package.provenance.gap_cells`
  (`ValuePlan.gap_cell_set()`, `{(sheet, row, col): what}`; an array / spill range keyed by its
  anchor), kept in the plan cache (`meta.json` `gap_cells`; a cache entry written before v15 is
  recomputed).
- **Unprefixed future functions** (answer to question 2 above, Patrick 2026-10-28): a modern function
  stored without its `_xlfn.` prefix (`=XLOOKUP(...)` from a sloppy writer) shows `#NAME?` in Excel
  too until the cell is re-entered → **genuine**, fail by code (`core/recalc.py` `XLFN_REQUIRED`,
  conservative list; `classify_lo_error` rule before the gap rules). `_xlfn._xlws.FILTER` / `SORT`
  are the stored forms LibreOffice 25.8 computes.
- **Gap list** verified against LibreOffice 25.8.7 (probe of 527 function names, 2026-10-28):
  added TRANSLATE, DETECTLANGUAGE, BINOM.DIST.RANGE, ECMA.CEILING, the CUBE functions, RTD, CALL,
  REGISTER.ID, SQL.REQUEST, DBCS, PHONETIC, THAIDIGIT, YEN; REGEXTEST / REGEXEXTRACT / REGEXREPLACE
  moved to the always-unsupported set. Re-run the probe on every LibreOffice upgrade
  (`LO_VERIFIED_VERSION`, docs/recalc.md).

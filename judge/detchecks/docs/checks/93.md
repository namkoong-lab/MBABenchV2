## Rule as implemented

Every worksheet, dialog sheet and macro sheet of the delivered workbook is graded: hidden
sheets, case tabs and agent tabs alike (whole workbook, no starting-file diff). Chartsheets have
no rows or columns. The check fails on any row or column that is hidden. A row counts as hidden
when any of these holds:

| hidden by | rows | columns |
|---|---|---|
| the hidden flag | `<row hidden="1">` | `<col hidden="1">` |
| a zero size of its own | `ht <= 0` (with or without `customHeight`) | `width <= 0` (with or without `customWidth`) |
| a zero sheet default | `sheetFormatPr zeroHeight="1"` (or `defaultRowHeight <= 0`): every row without a height of its own (a `<row>` without `ht`, or a row not written at all) | `defaultColWidth <= 0`: every column without a width of its own (no `<col>`, or a `<col>` without `width`) |

Empty hidden rows and columns count. So do hidden unused columns out to XFD: hiding the unused
grid counts as hidden. A zero default column width hides nothing when every column has its own
`<col>` width; this is toy T1's case, where only the explicit hidden columns are reported.

**The exemption: a collapsed outline group.** The rubric says "use grouping instead of
hiding". A hidden row is exempt when all of these hold:

1. it is hidden by the flag (`hidden="1"`), whatever its stored height
   (`FLAGGED_ZERO_SIZE_EXEMPT = True`). Excel itself writes `width="0" hidden="1"
   customWidth="1"` for hidden columns (Excel-saved toys 22 T4 and T6), so a stored zero next
   to the flag is ordinary Excel output, and the handoff exempts anything hidden inside a
   collapsed group. A zero height or width **without** the flag is not what collapsing writes;
   such a member is never exempt (it still counts as hidden when testing whether its run is
   hidden as a whole).
2. its `outlineLevel` L is 1 or more.
3. the maximal run of consecutive rows with `outlineLevel >= L` that contains it is hidden as a
   whole (every row of the run hidden by the flag or by zero height). This is exactly what
   collapsing a group produces. A row hidden inside an expanded group is hiding, not grouping.
   Rows that are not written have level 0 and end a run. Runs at a lower level contain the
   level-L run, so testing the level-L run is enough. Nested groups work: an inner group
   collapsed inside an expanded outer group is exempt; a collapsed outer group is exempt as a
   whole.
4. only when `REQUIRE_COLLAPSED_FLAG = True` (default False): the run's summary row carries
   `collapsed="1"`. That is the row after the run when `sheetPr/outlinePr summaryBelow` is on
   (the default), else the row before it.

Columns use the same test with `<col outlineLevel>`, `<col collapsed>` and `summaryRight`.

The decision comes from the rows' own `outlineLevel`, never from a `collapsed` flag alone. After
Excel's Ungroup, the summary row keeps `collapsed="1"` although no group exists (toy T3 Fail).
Outline symbols switched off do not cancel the exemption (`GROUP_NEEDS_OUTLINE_SYMBOLS = False`).
Neither does sheet protection.

**Mistakes.**
* One mistake per run of consecutive offending rows or columns that share a reason, located as
  `'Sheet'!259:263` or `'Sheet'!BT:XFD`.
* Runs are split by the reason AND by why they are not exempt, so each description is right
  for every row in it: no outline level (plus a stray collapsed mark next to it, if any); a
  partial hide inside an expanded group; a zero size without the flag inside a group; outline
  symbols off (option); a flagged zero-size member of a collapsed group (only with
  `FLAGGED_ZERO_SIZE_EXEMPT = False`). Rows inside an AutoFilter range say so (filtered-out
  rows count).
* A zero default row height gives one sheet-level mistake (location = the sheet name), with the
  number of rows it hides.
* Stats hold the per-sheet counts: hidden rows and columns, zero-size rows and columns, rows and
  columns exempt as collapsed groups, outline symbols, protection, near-zero sizes.

Only `<row>` attributes and the sheet head are read (`needs_rows`). No cell value is read, so no
GradingError comes from values. The engine still parses each sheet body, because rows are
streamed (93 T2: 160 MB sheet XML in 3.2 s).

## Edge-case decisions

* **Zero means zero.** `ZERO_ROW_HEIGHT_PT = ZERO_COL_WIDTH_CH = 0`. Near-zero rows
  (0 < ht < 0.75 pt) and columns (0 < width < 0.5 char) are not failed. They are listed in
  `stats.per_sheet[].near_zero_rows/cols`. A `baseColWidth="0"` default still leaves about 5 px
  of padding, so it is not zero.
* **Rows under `zeroHeight`.** A `<row>` without `ht` takes the sheet's zero default and is
  hidden. A row with its own `ht > 0` is visible. All default-height rows (written or not) are
  reported in the one sheet-level mistake.
* **AutoFilter / table filters.** Filtered-out rows carry `hidden="1"`, so they fail like any
  hidden row. The description names the filter range.
* **Hidden sheets** are graded. Their hidden rows and columns count, and the description says
  "(hidden sheet)". Hiding the sheet itself is 92's matter.
* **Protection.** A collapsed group on a protected sheet is still a group (not tested by any
  toy). It is recorded in stats (`protected`). report.md §3/§4b expected a fail (the reader
  cannot expand it); see Questions.
* **Flagged zero-size members** of a collapsed group are exempt (`FLAGGED_ZERO_SIZE_EXEMPT`,
  review fix 93-F1); unflagged zero sizes never are.
* **Grouped unused grid.** Columns BT:XFD hidden with `outlineLevel=1` (or every row of a sheet)
  form a whole hidden run, so they are exempt although no summary column can exist. See
  Questions.
* **`outlineLevelRow="0"` in sheetFormatPr** with rows carrying `outlineLevel` still counts as a
  group (the rows' own levels decide). Whether Excel draws the outline buttons then is
  unverified. See Questions.
* **Rows without `r=`** are numbered by the reader (previous + 1).

## Known limits

* Excel's display of a `<row>` without `ht` on a `zeroHeight` sheet is not verified (read as
  hidden). The sheet fails either way through the sheet-level mistake.
* `customSheetViews` (saved custom views with their own hidden rows) are not read; they are not
  the live view.
* Overlapping `<col>` ranges (invalid) go through the shared reading (`SheetHead.col_segments`, `core.sheet.paint_cols`):
  the later entry - by `min`, then file order - wins on the columns it covers, as a whole (hidden flag, width,
  outline level, collapsed mark), so a later visible entry clears an earlier hidden one. Until 2026-10-04 this
  sentence was already here but the column loop only ever added reasons (C:XFD hidden + D:D visible failed as
  C:XFD); the corpus showed no verdict change (CHANGELOG_core.md).

## Questions for Patrick

(Numbers kept from the earlier list; 8 is decided, see above.)

1. **Collapsed mark.** Should a hidden whole group need Excel's `collapsed="1"` on its summary
   row or column (`REQUIRE_COLLAPSED_FLAG`)? Default is no. Only corpus 1272 is affected (an
   openpyxl group of 333 rows without the mark), and it would then fail.
2. **Outline symbols off.** Should a collapsed group on a sheet with outline symbols switched off
   still count as grouping (`GROUP_NEEDS_OUTLINE_SYMBOLS`)? Default is yes. No toy or attempt
   has this.
3. **Near-zero sizes.** Should rows under 0.75 pt or columns under 0.5 char count as hidden?
   Default is no, because the rule says "zero". They are listed in stats. No attempt has any.
4. **Flagged zero-size group members** (review 93-F1). A `hidden="1"` row or column with a stored
   height/width of 0 inside a collapsed group is now exempt, because Excel writes
   `width="0" hidden="1"` for hidden columns. Keep (`FLAGGED_ZERO_SIZE_EXEMPT = True`), or fail
   them? No toy or attempt has this case.
5. **Protected sheets.** A collapsed group on a protected sheet passes. report.md expected a fail
   (the reader cannot expand it). Pass or fail? No toy or attempt has this case.
6. **AutoFilter.** Rows hidden by a filter fail (literal "hidden flag" rule; the description names
   the filter range). report.md asked for a ruling. Should filtered-out rows count as hidden? No
   attempt has a filter that hides rows.
7. **Grouped unused grid.** BT:XFD (or all rows) hidden with `outlineLevel=1` passes as a collapsed
   group, although no summary column/row can exist. The handoff says hiding the unused grid
   counts as hidden. Should a group running to XFD / row 1,048,576 be exempt? No attempt has it.
9. Concrete cases for question 3: a row at `ht="0.2"` (0 px) and a column at `width="0.01"` (0 px
   by Excel's formula) pass today.

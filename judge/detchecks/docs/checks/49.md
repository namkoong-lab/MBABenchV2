# 49 Formatting/Black font for calculations

Code: `detchecks/checks/c49.py`, shared rules in `detchecks/checks/colour_rules.py` (also used by 50 and 51).
Tests: `detchecks/tests/test_checks_colours.py`. Group: colours. Built 2026-10-02; review findings fixed 2026-10-03 (see "Review fixes 2026-10-03").

## Rule as implemented

Patrick's confirmed colour rule (handoff, rulings of 2026-10-02, applied fully 2026-10-03: 49 judges only OWN and CROSS cells; pointers are 50's, external links 51's). HYPERLINK navigation cells are ignored, also inside literal-only IFERROR / IFNA / IF guards (see "Decided 2026-10-03" and "Review fixes 2026-10-04"). Every formula cell of the delivered workbook is graded: every worksheet, macro sheet and dialog sheet, hidden or very hidden sheets and hidden rows included. Nothing is skipped as inherited.

**1. Class of a formula cell** (`colour_rules.Classifier`). Classification is syntactic: it uses the formula text, the defined names it uses (followed transitively, with Excel's scope rules) and the table parts. Cell values are never read, with one exception in 49: the own-sheet constant cell an `=INDIRECT(A20)` address comes from, when that decides a green cell (rule 5).

| class | when | 49 accepts |
|---|---|---|
| EXTERNAL | Reads another workbook anywhere: `[1]Prices!$C$5`, `'C:\p\[B.xlsx]S'!A1`, `[1]!Name`, a workbook-qualified name (`Other.xlsx!Rate` when no sheet has that name), a defined name whose definition reads another workbook, or a literal `INDIRECT("'[B.xlsx]S'!A1")`. Also a pure pointer to another workbook. | not judged by 49 (51 requires red) |
| POINTER | Otherwise, the whole formula is one reference to a cell or range on ANOTHER sheet of this workbook. Allowed around it: parentheses, unary `+` and `-`, `@`, a spill `#`, and the one-argument pass-through functions `ANCHORARRAY`, `SINGLE`, `TOROW`, `TOCOL`, `TRANSPOSE` (`POINTER_WRAPPERS`). Also counts: a defined name, or a chain of names, whose definition is such a reference (`=WACC` with `WACC = Inputs!$B$3`); a table reference on another sheet (`=Tbl[Col]`, `=Tbl[[#This Row],[Col]]`, `=Tbl[]`, and the bare table name `=Tbl`); a 3-D reference (`=Jan:Dec!B5`). | not judged by 49 (50 requires green) |
| CROSS | Otherwise, the formula reads another sheet of this workbook, directly, via a name, via a table (also a bare table name: `=SUM(Tbl)`, `BARE_TABLE_NAME_IS_REFERENCE`), or via an INDIRECT address known without evaluating anything (rule 5): `=Inputs!B5*C3`, `=SUM(Inputs!A1:A9)`, `=TOROW(Inputs!B5:B9,1)`, `=Inputs!#REF!`, `=INDIRECT("Inputs!B5")`. | black, green |
| OWN | Otherwise: only its own sheet, including self-qualified references (`='Monthly Model'!G66` on 'Monthly Model', sheet names compared case-insensitively), or no reference at all (`=5`, `=TODAY()`, `="x"`, `=IF(A1,"Inputs!B5",0)`). A HYPERLINK navigation cell (`=HYPERLINK(...)` alone, or inside IFERROR / IFNA / IF guards whose other arguments are literals; `colour_rules.is_hyperlink_formula`) is not graded at all (any colour). | black only |

**2. Which cells are formula cells.**
- Every `<c>` with its own formula counts: normal, shared master, shared child, array anchor or data-table anchor.
- Every non-anchor member of an array, dynamic-array spill or data-table range counts too. A member takes its anchor's class, but its own font colour is judged.
- A shared child takes its master's class: translation never changes sheets, names or shape. One exception: a POINTER master's child is re-classified on its own expanded text, because a reference pushed off the grid becomes `Sheet!#REF!`.
- What-if data-table cells (anchor and members) are OWN (`DATA_TABLE_CLASS`). Excel requires the table's input cells to be on its own sheet.
- Not counted (stats only): an empty `<f/>` marker outside any array range, and an array anchor stored without any formula text (`<f t="array" ref="A26:A76"></f>`, no value), together with its members.

**3. The colour that counts** is the cell's **font colour**: `cellXfs[s]` → `fonts[fontId].color`, resolved by `core.styles.Styles.resolve`. That covers rgb (alpha ignored), theme slot + tint (Excel's integer HLS tint; theme index 0 = lt1, 1 = dk1, 2 = lt2, 3 = dk2), indexed (custom `<indexedColors>` or the legacy palette; 64 = system foreground = black), auto, and no `<color>` = black. A colour that cannot be resolved (theme slot ≥ 12, indexed > 65, bad rgb) is never assumed black. Since 2026-10-04 (finding 47-R2-08) the core returns it as an explicit `UnknownColour` (`styles.is_unknown`) and also counts as unresolvable what it used to guess: an invalid entry of a custom `<indexedColors>` palette (read as black before), an rgb of other than 6 or 8 hex digits (its last six digits were used), a tint that is not a number in [-1, 1] (ignored / clamped before); resolvable colours are unchanged. The corpus has none on a formula cell (2026-10-04 scan: only `indexed="81"` comment fonts no cell uses), so no verdict changes Test `test_unresolvable_colours_2026_10_04` (test_checks_colours). Each check raises only when the cell's class makes its colour decide (49: an OWN or CROSS cell, or one whose class is unsure; 50: a pointer; 51: a cell reading another workbook); otherwise they skip it and count it in stats (`unresolved_colour_cells_not_needing_it`).
- Number-format colour tags (`[Blue]0`) are ignored (`NUMFMT_COLOUR_COUNTS = False`).
- Conditional-format font colours are ignored too (`CF_FONT_COLOUR_COUNTS = False`).
- The displayed-colour variant is not implemented. Switching either constant on raises at `start()`.

**4. Colour families** (HSV bands on the resolved RGB, `colour_rules.family`):
- **black**: v ≤ 0.20 at any hue, or s ≤ 0.25 with v ≤ 0.30. So 000000, 0D0D0D, 262626, 404040 ("Text 1, lighter 25%") and navy-black 0D0D26 are black. 595959 ("lighter 35%"), 808080, A6A6A6, D0CECE and 002060 are not.
- **green**: hue 75–165°, s ≥ 0.35, v ≥ 0.25. Includes 00B050, 008000, 00FF00, 006100, 276A3C, 375623, 548235, 92D050, and theme accent6 70AD47. Excludes 4472C4 and C6EFCE.
- **red**: hue < 15° or ≥ 340°, s ≥ 0.5, v ≥ 0.35. Includes FF0000, C00000, C0504D, 9C0006, 800000. Excludes FF6600 (orange), FF99CC (pink) and FFC7CE.

**5. Decision.** A cell is a mistake when its family is not accepted for its class (table above). The check works out only what the decision needs:
- **Black** cells are never classified, because black is accepted in every class.
- **Blue, grey, white, red and every other non-black, non-green colour** is wrong for OWN and CROSS, and not 49's business on a POINTER (check 50) or EXTERNAL (check 51) cell, so the class decides (counted in `pointer_cells_left_to_check_50` / `external_cells_left_to_check_51`). If the class cannot be worked out (malformed formula text, a table that does not exist, ...) and cheap conservative scans show the formula can be neither a pointer nor a reader of another workbook (`may_be_pointer`, `may_read_other_book`), the cell still fails with the reason `unclassified` (counted in `unclassified_offending_cells`); otherwise `GradingError`.
- **Green** cells need the class (OWN fails, the rest pass). A green formula that is CROSS, POINTER or EXTERNAL for sure by a cheap scan passes without a full parse (`colour_rules.quick_reads_other_sheet`, memoised per formula text, counted in `green_cells_accepted_by_direct_reference`): outside string literals and `[...]` groups it holds a sheet qualifier other than its own sheet followed by an A1 cell (`Inputs!B5`, `'My Sheet'!A1:B9`, `Jan:Dec!B5`, `[1]Prices!A1`), or an `INDIRECT(` call whose address starts with a string literal holding another sheet's or workbook's qualifier, followed by `&` and a non-string part (`INDIRECT("'Close Prices'!B"&(r+1))`, the same rule the classifier applies). Every other green cell is classified; a classification error raises.
- **INDIRECT addresses.** An address known without evaluating anything counts like a written reference:
  - a literal address (`"Inputs!B5"`, `"'[B.xlsx]S'!A1"`, `"Rate"`, `"Tbl"`);
  - a computed address whose leading string literal(s) hold the qualifier: `INDIRECT("'Stock Prices'!"&ADDRESS(r,c,4))` reads 'Stock Prices', `INDIRECT("Calc!B"&ROW())` reads Calc, `INDIRECT("'[B.xlsx]S'!B"&n)` reads another workbook;
  - an address assembled with `&` from string literals, `ADDRESS(...)` calls with no (or an empty) sheet argument or a literal one, and numeric parts (numbers, arithmetic, and `NUMERIC_FUNCS` calls such as `ROW()`, `COLUMN()`, `MATCH(...)`, whose text can never add a `!`): `INDIRECT("B"&ROW())` and `INDIRECT(ADDRESS(r,c))` are own-sheet, `INDIRECT(ADDRESS(ROW(),2,4,TRUE,"Inputs"))` reads Inputs. If such an address could spell a defined name or table (`"Rate"&ROW()`), it stays unknown.
  - **An address held in one own-sheet cell** (`=INDIRECT(A20)*2`): when it decides a green cell that is otherwise OWN, the engine streams that sheet a second time and reads the cell (`INDIRECT_READ_ADDRESS_CELL`). A constant text that is a reference to another sheet or workbook makes the cell pass; any other constant (another own-sheet address, a number, an empty cell: INDIRECT returns #REF!) makes it an own-sheet formula in green, which fails. If the address cell holds a formula, its value would be needed and the check raises `GradingError` (49 does not read formula values).
  - Any other computed address (`=INDIRECT(A20&B20)`, `=INDIRECT(TEXT(ROW(),"0"))`) is unknown. A green cell whose class is OWN only for that reason raises `GradingError` (no guess). In another non-black colour the cell fails (it is OWN or CROSS either way, and a computed INDIRECT is not considered to reach another workbook (INDIRECT cannot read a closed workbook; see Q8). Since 2026-10-04 such a cell is reported with the reason `indirect` ("formula whose INDIRECT address is built from cell contents ... this colour is wrong either way", `c49.INDIRECT_UNKNOWN`) rather than as "formula using only its own sheet", because the address cell is not read for it (a blue `=INDIRECT(A20)` with A20 = `Inputs!B5` does read another sheet).
- **Defined names with an unknown scope** (a `localSheetId` that names no sheet): a reference to such a name may resolve to it or to a same-named definition (or to nothing). If every possible definition is inert (constants such as `0.05`), nothing changes and nothing is raised. Otherwise 49 raises only where the outcome could differ: a green cell that reads another sheet only through such a name (or is OWN apart from it), or a non-green cell that may be a pointer or read another workbook only through such a name. A green cell with its own direct reference to another sheet is decided without it.

**6. Verdict.**
- Offending cells are grouped per sheet and per (class, exact colour) into rectangles; there is one mistake per rectangle (severity major, capped at 25).
- Each mistake's description gives the range, the cell count, the class, the colour name with its hex, the rule, and an example formula. The example is translated for shared children, "spilled from X" for members and "what-if data table at X" for data tables.
- Stats: formula cells, members examined, ignored markers and text-less arrays, counts per colour family (incl. `unresolved`), cells classified per class, offending cells by reason (`own`, `cross`, `indirect`, `unclassified`) and by sheet; `hyperlink_cells_ignored`; for 49 also `green_cells_accepted_by_direct_reference`, `unclassified_offending_cells`, `indirect_address_cells_read`, `pointer_cells_left_to_check_50` and `external_cells_left_to_check_51`.

## Edge-case decisions (constants in `colour_rules.py` / `c49.py`)

- **Pointers and externals are NOT judged by 49** (`c49.NOT_JUDGED`; ruling 2026-10-03, see "Decided 2026-10-03"). 49 judges OWN (black) and CROSS (black or green) only: a blue pointer fails 50 only, a blue external link or calculation fails 51 only. (Until 2026-10-04 this bullet still described the pre-ruling double penalty, `c49.ALLOWED` for all four classes; finding 49-R2-2.)
- **Constant-only formulas** (`=5`, `=1`, `=1000*12`, `=DATE(2025,1,1)`) are OWN, so they must be black. Per the rule ("no references → black"), the report's "typed hardcode" exemption was not adopted.
- **Formulas returning "" or text, check/status formulas, light text on dark fills**: no exemption. They are classified like any formula (Patrick: do not invent exemptions). See the questions below. HYPERLINK navigation cells are the one ruled exemption (2026-10-03; guarded forms 2026-10-04).
- **Spill / array members**: their class comes from the anchor's formula and their colour from their own style. Anchor-only and every-cell readings agree on the toys.
- **Data tables**: OWN (`DATA_TABLE_CLASS`).
- **Self-qualified references** (`=Calc!B2` on Calc) are own-sheet (case-insensitive).
- **Names**: a name is followed to its definition; an unqualified reference inside a name is on the using sheet, as in Excel. A name with an unusable `localSheetId` (unknown scope) raises only where its possible definitions could change the decision (rule 5).
- **Tables**: a structured reference (`Tbl[Col]`, `Tbl[[#This Row],[Col]]`, `Tbl[]`) is placed on its table's sheet (`pkg.tables`, read from the table parts at start). A bare table name used as a reference (`=SUM(Tbl)`, `=Tbl`) is treated the same (`BARE_TABLE_NAME_IS_REFERENCE = True`): Excel keeps table names and defined names in one namespace, and `=Tbl` is the table's data body. A table name that does not exist raises where the class is needed (green or red cells). If the table parts cannot be read, a formula raises only when it uses a structured reference or a name that is not a defined name.
- **INDIRECT**: see rule 5. The leading-literal case was added after the first sanity run (gpt6 1340, 1570, 1601 build `"'Close Prices'!B"&(row)` addresses in green cross-sheet cells and had raised); the assembled-address and address-cell cases were added after the 2026-10-03 review. Text that is not a reference reads nothing (INDIRECT returns #REF!).
- **Hidden rows, columns and sheets** are graded. Mistakes on a hidden sheet say "(hidden sheet)".

## Policies already set, and their effect here

- **Writer trust (openpyxl/XlsxWriter caches untrusted)**: no effect. 49, 50 and 51 never read a formula's value (49 reads only constant INDIRECT address cells, which are not caches; an address in a formula cell raises), so they grade openpyxl and XlsxWriter files without needing caches or a `value_path`.
- **Malformed formula text raises (FormulaError)**: the text is parsed only when the decision needs the class. For 49 that means green and red formula cells, minus green cells with a direct reference to another sheet (accepted by the quick scan). A malformed formula in a black cell, or in a blue/grey/white one (which fails anyway, reason `unclassified`), does not make 49 raise; one in a green cell without a direct other-sheet reference does (unit-tested).

## Known limits

- A computed INDIRECT target is evaluated only in the cases of rule 5 (syntactically known parts, or one own-sheet constant address cell); an address in a formula cell, or built from cell contents in any other way, raises for a green cell. OFFSET targets are not evaluated (OFFSET needs a reference argument, which already decides the sheet).
- The assembled-address stand-in assumes the numeric parts give ordinary positive numbers (a negative or fractional row would make the real address #REF!).
- An address read from a cell is parsed in A1 style even when INDIRECT's second argument asks for R1C1; only the sheet it names matters here.
- The colour bands are a proposal: House Standards names the colours but gives no RGB.
- Number-format colours and conditional formats are ignored (decision; see Q7).
- Shared children are classified by their master's text. This is exact apart from off-grid `#REF!`, which is handled for pointers, the only class it can change.
- The classification cache and 49's quick-scan memo each hold at most 200,000 distinct (sheet, formula) entries; beyond that, formulas are re-scanned or re-parsed (slower, same result).

## Decided 2026-10-03

Patrick's rulings of 2026-10-03 (former questions 1, 2, 4 and 10):

- **HYPERLINK navigation cells may be any colour** (former Q1; Patrick's words: "HYPERLINK cells any colour", rationale "not a calculation"; the question put to him counted 58 files failing on nothing else, a figure that included the IFERROR-guarded cells below). A formula cell is a navigation cell and is ignored by 49, 50 and 51 (`colour_rules.is_hyperlink_formula`) when, after optional whitespace and one leading `=`, the whole formula is one built-in `HYPERLINK(...)` call, or (since 2026-10-04, finding 49-R2-1) one of the guards `IFERROR`, `IFNA`, `IF` (`colour_rules.HYPERLINK_GUARDS`) around such a call whose every other argument is a single literal or empty; guards may nest and the HYPERLINK call's own arguments are free. Ignored: `=HYPERLINK("#'Cover'!A1","Cover")`, `=HYPERLINK(Inputs!B5)`, `=IFERROR(HYPERLINK("#'Summary'!A1","OPEN"),"OPEN")` (the ChatGPT writer's pattern), `=IF(TRUE,HYPERLINK(...),"")`. Still graded as ordinary formulas: `=IF(B9>0,HYPERLINK(...),"")` (the condition reads a cell), `=IFERROR(HYPERLINK(...),C1*2)` (the fallback calculates), `=HYPERLINK(...)&""`, `=(HYPERLINK(...))`, `=+HYPERLINK(...)`, HYPERLINK inside any other function. The 2026-10-03 implementation exempted only the bare top-level call; that narrow reading was the implementer's, not part of the ruling (see Q11 for the remaining boundary). Spill members and shared children follow their anchor's / master's text. Counted in `hyperlink_cells_ignored`. Tests: `test_hyperlink_cells_any_colour`, `test_hyperlink_guarded_navigation_cells`.
- **Light text on dark fills: no exemption** (former Q2). Header formulas follow the normal colour rule; only the font colour counts (unchanged behaviour). Example: attempt 2192 `FCFF!B4:O4 =Tax!B4` (white on a dark fill) should have been green (a 50 mistake). Test: `test_light_text_on_dark_fill_no_exemption`.
- **Pointers are judged by 50 only, external links by 51 only** (former Q4; the confirmed rule applied fully). 49 judges own-sheet formulas (black) and cross-sheet calculations (black or green). A blue pointer fails 50 only; a blue external link fails 51 only. Test: `test_pointers_judged_only_by_50`.
  - Note for Patrick: the ruling names pointers explicitly; external links (51's class) were taken out of 49 as well, following "49 judges own-sheet formulas and cross-sheet calculations". An external **calculation** in a non-red, non-black colour (e.g. blue `=[1]Rates!B2*C25`) is therefore judged by 51 only.
- **Near-empty attempts / workbooks without formulas: no completeness gate** (former Q10). Python verdicts stand; a workbook without formulas passes 49, 50 and 51. Test: `test_near_empty_attempt_no_gate`.

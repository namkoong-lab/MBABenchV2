# 50 Formatting/Green font for cross-sheet links

Code: `detchecks/checks/c50.py`, shared rules in `detchecks/checks/colour_rules.py`. Shared material (formula classes, which cells count, colour resolution, colour families, policies) is documented once in `docs/checks/49.md`; this page covers what is specific to 50.
Tests: `detchecks/tests/test_checks_colours.py`. Group: colours. Built 2026-10-02; review findings fixed 2026-10-03 (see "Review fixes 2026-10-03" in 49.md).

## Rule as implemented

**Scope.** Every formula cell of the delivered workbook whose class is **POINTER** must have a font in the **green** family. All sheets count, hidden ones included, and nothing is exempt as inherited. Every other formula cell is ignored by 50, and so is a HYPERLINK navigation cell (ruling 2026-10-03). Pointers are judged by 50 only: 49 no longer also fails a non-green pointer (2026-10-03).

**What a POINTER is.** It is a formula that reads no other workbook and whose whole text is one reference to a cell or range on another sheet of this workbook. That reference may be wrapped in any of the following:
- parentheses;
- unary `+` or `-`;
- `@`, or a spill `#`;
- one-argument `ANCHORARRAY`, `SINGLE`, `TOROW`, `TOCOL` or `TRANSPOSE`.

A defined name or a table reference counts as such a reference when it resolves to another sheet: `Tbl[Col]`, `Tbl[[#This Row],[Col]]` (how Excel stores `[@Col]`), `Tbl[[#Totals],[Col]]`, `Tbl[[#Headers],[Col]]`, `Tbl[]`, and the bare table name `Tbl` (`BARE_TABLE_NAME_IS_REFERENCE`).

Examples:
- POINTER: `=Inputs!B5`, `=-Inputs!B5`, `=(Inputs!B5)`, `=Comp!$A$5:$A$19` (spilled), `=ANCHORARRAY('X'!$H$641)`, `=TOROW('1_Historical_Data'!$C$5:$C$40)`, `=WACC` (WACC = `Inputs!$B$3`), `=Tbl[Col]` (table on another sheet), `=Jan:Dec!B5`.
- Not a POINTER: `=Inputs!B5*C3`, `=TOROW(Inputs!B5:B9,1)`, `=INDIRECT("Inputs!B5")` (a function, not a reference), `='Monthly Model'!G66` on 'Monthly Model' (its own sheet), `=[1]Prices!A1` (another workbook, check 51).

**Spills and arrays.** Spill / array members take the anchor's class, and each member's own font colour is judged. When the anchor is black and its members are green (toy T2), only the anchor is flagged.

**No convention vote.** The judge note's majority rule ("determine the model's own convention…") is superseded by Patrick's confirmed rule: pointer → must be green. One black pointer among thousands of green ones fails.

**Optimisation.** Green cells are never classified. A non-green formula is parsed only if a conservative pre-filter (`Classifier.may_be_pointer`) says it could be a pointer. The pre-filter requires a `!`, a `[`, or an identifier spelled like a defined name or table, and rejects any operator other than unary `+`/`-`, any argument separator and any string literal. String literals, quoted sheet names and `[...]` groups (book indexes and structured-reference specs, whose commas and `#This Row` belong to the reference) are masked first, and one leading `=` stored inside `<f>` (tolerated by the parser) is ignored. Since 2026-10-04 it also requires the **shape of one reference** (`colour_rules.pointer_shaped`): on the masked text, a head of `(`, unary `+`/`-`/`@` and one-argument wrapper calls (`_xlfn.TOROW(`, any `_xl*.` prefix), then one operand holding no whitespace and none of `( ) + - @`, then a tail of `)`, spill `#` and stray `+`/`-`/`@` (the parser tolerates a trailing operator, so the tail keeps the test conservative), with the head's `(` all closed in the tail. A call other than the wrappers (`=SUM(Inputs!A1:A5)`, `=SUM(Nope[Col])`), two operands (`=Inputs!B5+Nope[Col]`, the intersection `=Inputs!A1:A5 Nope[Col]`) or unbalanced parentheses (`=SUM(Inputs!A1:A5`, `=TOROW(Nope[Col]`) can never be a pure reference, so such text is never parsed and cannot make 50 raise, whatever the unknown table or malformed text would do in the classifier.

**Colour that cannot be resolved.** 50 raises only when the cell is a pointer (or may be one, see below); any other formula cell with an unresolvable font colour cannot fail 50 and is skipped (stats `unresolved_colour_cells_not_needing_it`).

**Defined names with an unknown scope** (bad `localSheetId`): a formula that is only such a name (`=Rate`, `=-Rate`) may or may not be a link, depending on which definition applies, so 50 raises there unless every possible definition is inert (a constant: then it is no link). Any other formula using such a name cannot be a pointer and is decided without it.

**Mistakes.** One per rectangle of offending cells, per sheet and per exact colour. Each says "link to another sheet … in {colour} font; cross-sheet links must be green" and gives an example formula.

## Edge-case decisions

- **Wrappers** (`POINTER_WRAPPERS`): ANCHORARRAY and SINGLE are how Excel stores `#` and `@`. TOROW, TOCOL and TRANSPOSE with one argument only reshape. Toy 50/T4 calls the TOROW form "a pure cross-sheet pull", so they count.
- **Unary minus** (`POINTER_ALLOWS_NEGATION = True`): `=-Inputs!B5` is a sign-flipped link, so it must be green. Example: corpus attempt 1709, `NAV!D25 =-NetDebt` (a name on another sheet), black, so it is flagged.
- **Names and tables**: a pure name or table reference that resolves to another sheet is a pointer; if it resolves to a constant or to its own sheet, it is not.
- **Text-returning links** (title pulls `=Assumptions!$A$1`) are pointers like any other. The Pass toys recolour them green, so no text exclusion applies.
- **Light text on dark fills** (white header pulls): no exemption. See 49.md, Q2.
- **Off-grid shared children**: the child of a pointer master that is pushed off the grid (`Inputs!#REF!`) is not a pointer. It is re-checked on its own text (unit-tested).
- **External pointers** (`=[1]Prices!A1`) are check 51's business.
- **Literal INDIRECT pulls** (`=INDIRECT("Inputs!B5")`) are function calls, so they are CROSS calculations (black or green), not links (Q5).

## Known limits

- The pre-filter is conservative: it never hides a pointer (unit-tested on every pointer form, `test_prefilters_are_conservative`, `test_structured_refs_with_commas_are_pointers`, `test_leading_equals_pointer`, `test_checks_50.test_prefilter_rejects_shapes_that_cannot_be_pointers`; and over all 1,623,195 distinct formula texts of `scratch/all_formulas.jsonl.gz` every text the parser sees as a pure reference passes the shape test, `scratch/rereview/50/shape_soundness.py`). Before the 2026-10-03 fix it rejected structured references containing a comma (`Tbl[[#This Row],[Col]]`, 0 occurrences in the 374 sanity files) and a leading `=` inside `<f>`. A malformed formula that the pre-filter rejects is not parsed, so it does not raise in 50.
- **What still raises** (deliberately, no guess): a text of pointer shape whose class cannot be worked out - a pure structured reference or bare name of a table that does not exist (`=Nope[Col]`, `=-Nope[Col]`, `=TOROW(Nope[Col])`), a pure defined name with an unknown scope (see above), and malformed text that looks like one reference (`=Inputs!`, `=Inputs!A1:`, an unterminated `'Sheet!A1`, `=Inputs!B5 #`). Excel would not store any of these; whether such a cell is a link cannot be decided from the text, so 50 raises rather than passing or failing it.
- A computed INDIRECT is never a pointer (it is a function call).
- See 49.md for the shared limits.

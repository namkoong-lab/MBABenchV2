## Rule as implemented

| delivered name | file content | verdict |
|---|---|---|
| `.xlsx` (any letter case) | a macro-free workbook package: main content type `...spreadsheetml.sheet.main+xml`, no macro part loaded | **pass** |
| `.xlsm` (any letter case) | a macro-enabled workbook package (`...ms-excel.sheet.macroEnabled.main+xml`) that loads at least one macro part | **pass** |
| `.xlsm` | macro-enabled package without a macro part (toys T1, T2) | fail |
| `.xlsx` | a package that loads macros (VBA project or XLM macro sheet) | fail ("must be .xlsm") |
| `.xlsx` / `.xlsm` | a package whose type disagrees with the name: a macro-enabled package named .xlsx; a plain package named .xlsm; template/add-in content; .xlsb, .xls (BIFF), CSV/text, ODS, or a zip that is not a workbook (renamed .docx) | fail ("extension and file format disagree"; Excel refuses such a file) |
| anything else (.xls, .xlsb, .csv, .ods, .xltx, .xltm, .xlam, no extension) | whatever the bytes | fail on the name alone |

Further points:
- **Delivered name.** Production stages every delivery as `ai_attempt.xlsx`. The original name is therefore taken from `task_meta["delivered_filename"]` when it is given and not None (a path is cut to its last component). Otherwise the file's own name is used. `stats.filename_source` is `task_meta.delivered_filename` or `file_name`. An empty or non-string value raises. In the corpus the original name sits in `corpus/attempts/<id>/_attempt_origin.json` (`original_filename`), and the corpus files already carry that name.
- **Staging name without a delivered name raises** (review fix 2026-10-03, finding `77-staged-name-fallback`). When no delivered name is given and the file itself is named `ai_attempt.xlsx` (any case; `STAGED_FILE_NAMES`), its own name is known not to be the delivered one: the judge guidance says "never from the staged name", and grading it would silently fail a real .xlsm with VBA (and pass a plain package delivered under a wrong name). The check raises GradingError instead. If task_meta carries the sidecar key `original_filename` but not `delivered_filename`, the message says so (the caller must map the key; the check does not read the sidecar key itself). Any other file name is still graded as delivered (toys, corpus).
- **Macro part.** This is a part Excel loads as macros:
  - a VBA project: a `vbaProject` relationship from the workbook part, with the part present and a **real VBA project** — an OLE2 compound file whose root holds a `VBA` storage with a `dir` stream, and a `PROJECT` stream (MS-OVBA 2.2; review fix 2026-10-03, finding `77-vba-signature-only`: before, the 8-byte OLE2 signature alone counted, so a signature followed by zeros, or an .xls compound file, passed as macros). The directory tree is walked with the stdlib (`vba_project_status` in c77.py), names compared case-insensitively;
  - or an Excel 4.0 macro sheet: an `xlMacrosheet` / `xlIntlMacrosheet` relationship.
- A `*vbaProject.bin` that nothing relates is not loaded (OPC reaches parts through relationships). It is listed in `stats.unrelated_vba_files` and named in the .xlsm failure. Not macros either (`stats.invalid_vba_parts`, part → reason): a related vbaProject that is not an OLE2 file, whose compound-file header breaks MS-CFB's MUST rules (byte order, sector size), or that lacks the VBA storage, its dir stream or the PROJECT stream. A macro relationship to a missing part (`missing_vba_parts`) is not macros.
- A related vbaProject with a valid header whose directory cannot be walked (sector out of range, chain loop) is `stats.unreadable_vba_parts`: whether it holds macros is unknown, so it raises when it decides (no other macro part).
- An **empty** VBA project (structure present, no modules) counts as present. The check looks at structure, not substance; VBA source is not decoded.
- The **producer is not judged**: an .xlsx written by LibreOffice, openpyxl or Excel Online passes. `stats.application` records it.
- This is the only check that grades files the reader cannot parse (`accepts_unparsed = True`). Classification comes from `Package` (zip / OLE2 directory / content types); no sheet is opened.

### Mistakes

- Exactly one per failing file. The location is the delivered file name.
- The description says what the name claims and what the file is. Severity is major.

Stats:
- name: `delivered_filename`, `filename_source`, `staged_file_name`, `extension`
- package: `container`, `reader_format`, `package_kind`, `package`, `main_part`, `main_content_type`
- macros: `has_macros`, `macro_parts`, `invalid_vba_parts` and `unreadable_vba_parts` (part → reason), `missing_vba_parts`, `unrelated_vba_files`, `dialog_sheets`
- other: `ole2_streams`, `application`, `unsupported_reason`, `size`

### No guess (GradingError)

- the file carries the staging name `ai_attempt.xlsx` and no delivered name is given (above).

These cases raise only when the name is .xlsx/.xlsm, because any other name fails on the name alone:
- an empty file;
- a damaged zip (corrupt package structure);
- a password-encrypted package (OLE2 `EncryptedPackage`), whose inner type cannot be seen;
- an OLE2 file whose directory cannot be read (it could be an encrypted .xlsx or an .xls);
- a package whose workbook part has a generic content type (`application/xml`, none): the package does not declare whether it is .xlsx or .xlsm;
- a related vbaProject whose compound-file directory cannot be walked, when no other macro part decides;
- an Excel 5.0 dialog sheet as the only macro-like content (`DIALOG_SHEET_POLICY = "error"`): whether Excel requires .xlsm for it is unverified.

## Edge-case decisions

- A name other than .xlsx/.xlsm fails without looking at the content, so a corrupt or encrypted file named .xls fails instead of raising. The decision does not need the content.
- An .xlsx name with macro-enabled content fails as a mismatch, before any macro question.
- **Corpus attempts (71) and the 303 GPT-6 files** (census `detchecks/scratch/views/census_pkg.py`, and `run_corpus --checks 61,62,77`):
  - All 374 are .xlsx with the sheet.main content type, no VBA project and no vbaProject file. All 71 attempt sidecars name an .xlsx.
  - **77 passes 374/374, 0 errors.**
  - Producers: 109 openpyxl, 72 LibreOffice, 10 Excel, 5 Excel Online, 178 without app.xml. None is judged.

## Known limits

- An empty VBA project (no modules) counts as macros present.
- Excel 5.0 dialog sheets raise (unverified).
- ActiveX controls, printer settings and other binaries are not macros (correct per OPC, unverified in Excel).
- `task_meta["delivered_filename"]` must be supplied by the production caller (production's sidecar key is `original_filename`, written best-effort by grade_from_db). Without it a file named `ai_attempt.xlsx` raises. `tools/run_corpus.py` and `tools/grade_one.py` do not pass it; corpus files carry their original names, so the result is the same there.
- The VBA test is structural (VBA storage + dir + PROJECT). A project with that structure but corrupt stream contents counts as macros.

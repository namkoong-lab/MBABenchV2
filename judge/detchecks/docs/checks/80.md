## Rule as implemented

**Fail** when any formula site calls one of the rubric's eight volatile functions:
`INDIRECT, OFFSET, TODAY, NOW, RAND, RANDBETWEEN, INFO, CELL` (constant `VOLATILE`).
`RANDARRAY` (listed in `formula.VOLATILE_FUNCTIONS`) is **not** counted; every occurrence is
reported in `stats.randarray_sites_not_counted` / `randarray_examples`.

Formula sites scanned (whole delivered workbook, hidden sheets included, no starting-file diff):

| site | how |
|---|---|
| cell formulas on worksheets and macro sheets | normal, array and shared formulas. A shared group is classified once from its master text; every child inherits the master's result (which functions a formula calls never changes when Excel copies it). A child without an earlier master raises `GradingError`. Spill/array members carry no formula of their own; data-table anchors have none |
| defined names | a name whose own definition calls a volatile function counts **when a formula site uses it**, directly or through other names (visible or hidden, built-in or not). Uses: cell, CF and DV formulas (incl. a literal `INDIRECT("Name")`), chart series, sparklines, shape text links, form controls (`xl/ctrlProps`: `fmlaRange`, `fmlaLink`, `fmlaTxbx`, `fmlaGroup`, e.g. a combo box fed by `DynList`), pivot caches built on the name. A built-in name counts as used whether a formula writes `Print_Area` or `_xlnm.Print_Area`. A volatile name nothing uses (e.g. GPT-6's dynamic `_xlnm.Print_Area = OFFSET(...)`) is listed in `stats.volatile_names_unused_not_counted` (`COUNT_UNUSED_NAMES = False`) |
| conditional formats | every rule formula and every colour-scale / data-bar / icon-set threshold (`<cfvo val=..>`, x14 `<x14:cfvo><xm:f>`), main and x14; a `timePeriod` rule without a stored formula counts as TODAY (`CF_TIME_PERIOD_IS_TODAY = True`; Excel evaluates it with TODAY()) |
| data validations | `formula1`/`formula2`, main and x14 |

A "call" is a call found by `detchecks.core.formula.parse`, of a built-in function, not a
LET/LAMBDA parameter: `c.builtin and not c.local`. So these never count: function names in
text cells or inside string literals (`="TODAY()"`, `=N("uses OFFSET(A1,1,1)")`), a column
named NOW (`'Annual Summary'!NOW$2`, toy 80/T6 Pass), a LET parameter called `today`,
`_xludf.TODAY()` (a user function). These do count: range-ending calls
(`SUM(D5:OFFSET(D5,0,3))`), eta values (`BYROW(r,_xleta.RAND)`), lower-case
openpyxl text (`offset(a1,1,0)`), TAB/CR inside the text, legacy array formulas.

**`NAME (` spellings are undecidable** (2026-10-04, second review). A volatile function name
written with whitespace before its `(` (`OFFSET (A1,1,1)`, `RANDBETWEEN\n(1,9)`) is not a call
to `core.formula` (a NAME beside a parenthesised group), and how Excel reads such *stored*
text is not measured (question 11). The check does not guess either way: such a site (cell,
CF or DV formula; a defined name that a formula uses; a referenced `TODAY ()` stamp) is
undecidable (`spaced_volatile_names`, bare names only: `S!OFFSET (`, `Tbl[Today (x)]`, a sheet
`'Now (2)'` and `NOW:NOW (A1)` are not). An unused defined name spelled this way decides
nothing (`stats.space_call_names_unused`); an unreferenced `TODAY ()` stamp passes whatever
Excel reads. See "Undecidable sites" below.

A cell that uses a volatile **name** is not a separate mistake: the name is the mistake, and
its description lists how many formula sites use it, directly or through other names
(chains `Total=SUM(Base)`, `Base=OFFSET(...)`: only `Base` is flagged; its users include the
cells that use `Total`; LAMBDA names called as `=MyFn(3)` count as uses; a dynamic chart
range `Series = Data!DynRng` with `DynRng = OFFSET(...)` makes `DynRng` used). The tally
stops parsing once a name has 3 uses (`_fscan.USE_TALLY_SATURATION`; the verdict needs one):
the description then says "used by at least N formula sites".

Names whose `localSheetId` names no sheet (the reader's `scope` raises for them) are left
out of name resolution: no formula on an existing sheet can see them. Such a name makes a
volatile name's use undecidable when it is itself volatile, or its definition mentions a
volatile name, **and** that volatile name is not otherwise used; the check then raises
`GradingError` only if no other mistake fails the file (see "Undecidable sites").

Pre-filter: `formula.quick_may_call(text, the 9 names)` (string literals masked). A text
that does not mention any of the names outside string literals is not parsed. Texts are
parsed with `formula.parse` minus its lru cache (`_fscan.parse_text`): each cell text is
parsed once, and on gpt6 attempt 1476 (35 MB, 662k distinct OFFSET formulas) the cache held
~510 MB (peak 678 MB -> 167 MB, 40 s -> 32 s).

### Date-stamp exception

Rubric: "Volatile functions are avoided except where clearly justified (e.g., date-stamping)".
Handoff: "TODAY/NOW alone in a cell that nothing references (a date stamp)".

* **Alone**: the whole cell formula is `TODAY()` or `NOW()`, optional spaces and `=`, plus
  the no-op wrappers Excel keeps exactly as typed: leading unary `+` / `@` and redundant
  parentheses (`=+TODAY()`, `=(NOW())`, `=@TODAY()`, `=+(+TODAY())`; regex `_RE_STAMP`,
  case-insensitive, parentheses must balance; 2026-10-04, question 12). Anything else makes
  it not alone and it fails: `="Prepared "&TEXT(TODAY(),"d mmm yyyy")`, `TODAY()-D6`,
  `INT(NOW())`, `TODAY()+0`, `-TODAY()`, `(NOW())*1`, `TEXT(TODAY(),"yyyy-mm-dd")` (a change
  log: corpus 4091 fails on exactly this). Every child of a shared `TODAY()` group is its own
  stamp candidate; a multi-cell array `{=TODAY()}` is one candidate covering its range.
  `TODAY ()` (space before `(`) is a candidate too: unreferenced it passes, referenced it is
  undecidable (question 11).
* **Nothing references it**: no reference anywhere in the workbook whose area contains the
  cell. Checked places:
  * every cell formula of every sheet: cells, ranges, whole columns/rows (`COUNT(C:C)`),
    trimmed ranges, spill anchors, 3-D spans (`SUM(Cover:Calc!C6)`), table references
    (placed through the table's range), shared children (master references shifted by the
    child's offset; copies pushed off the grid are #REF! and reference nothing), and the box
    spanned by a range operator between a reference and a function (`A1:INDEX(E1:E10,8)` covers
    A1:E10);
  * defined names (non-built-in), used or not: unqualified references inside a name mean
    "the sheet that uses it" and relative parts move with the using cell, so they are taken to
    reach every sheet / row / column (conservative);
  * CF formulas incl. colour-scale / data-bar / icon-set thresholds, and DV formulas
    (relative references expanded over the whole `sqref`), sparklines, data-table input cells
    (`r1`/`r2`), chart series (`<c:f>`), shape text links, form controls (`ctrlProps`),
    pivot-cache sources (sheet range or table).
  * ranges whose endpoints are defined names (`SUM(Start:End)`, `SUM(A1:End)`): placed
    through the names when each is one fixed absolute reference (the box between them counts,
    even if neither name covers the stamp). An undefined endpoint is `#NAME?` and references
    nothing; a dynamic or relative endpoint (`End = INDEX(..)`) cannot be placed: an
    undecidable site (raises `GradingError` only when the verdict depends on it).
  * built-in names (`Print_Area`, `Print_Titles`, `_FilterDatabase`) covering the stamp
    reference it **only when a formula uses the name** (`=COUNT(Cover!Print_Area)`); an
    unused print setting does not (`STAMP_IGNORES_BUILTIN_NAMES = True`).
  * Not references: the CF/DV *ranges* a rule applies to, hyperlinks.
  * Dynamic references (INDIRECT/OFFSET) are not followed: such a workbook fails anyway.
* A referenced stamp is a mistake at the stamp cell ("would be a date stamp, but it is
  referenced by N formula sites (...)"). Unreferenced stamps are listed in
  `stats.date_stamps_exempt` and mentioned in the summary.
* No sheet-name condition: the stamp may sit on any sheet (see question 4).
* Cost: when a candidate exists, the check asks the engine for a second streaming pass of
  every sheet that holds formulas (`stats.stamp_second_pass_sheets`). A per-cell pre-filter
  parses only formulas that can reach a candidate's sheet (sheet name in the text, a 3-D
  qualifier, a table that holds a candidate, or on the stamp's own sheet a range / the
  stamp's address); shared masters on the stamp's sheet are always parsed.

### Undecidable sites (no guess, no avoidable raise)

Some sites cannot be decided from the file: a volatile name whose use cannot be traced (a
name with a `localSheetId` that names no sheet is on its chain), a stamp reference that cannot
be placed (dynamic or relative name endpoint, a table that does not exist), and a `NAME (`
spelling (above). They are collected during the scan and decided in `finish()`:

* some other mistake already fails the file -> the verdict is a certain fail; the sites are
  recorded in stats (`volatile_names_use_undecidable`, `date_stamps_undecided`,
  `stamp_refs_unplaced`, `space_calls_undecided`) and counted in the summary ("N undecidable
  sites recorded in stats (the verdict does not depend on them)");
* otherwise the verdict depends on them -> `GradingError` naming the first site (no fallback).

An unplaceable stamp reference matters only for stamp candidates nothing else references (a
referenced stamp is a mistake whatever the unplaced reference covers). Since 2026-10-04
(second review, finding 80-avoidable-gradingerror); before, these raised even when another
cell already failed the file, and `api.grade` then returned no verdict for any check.
Still raised immediately (unchanged policy): a shared child before its master, malformed
formula text that mentions a volatile name, an unreadable table `ref`.

### Mistakes

* `Name Manager: <name>` (or `Name Manager: 'Sheet'!<name>` for a sheet-local name) - one
  per volatile name, listed first.
* `'Sheet'!<range>` - cell formulas grouped into rectangles per sheet and per set of
  functions; description shows the top-left formula.
* `'Sheet'!<sqref>` - one per CF block / DV with a volatile formula.
* `'Sheet'!<cell>` - referenced date stamps.

## Known limits

* VML (legacy) form-control formulas, ActiveX, pivot calculated fields, Power Query and VBA
  are not read.
* Data-table anchors (`TABLE()`) are not volatile here.
* Stamp references through INDIRECT/OFFSET are not followed (the workbook fails anyway).
* A reference whose area cannot be placed (a range whose name endpoint is not one fixed
  absolute reference, e.g. `A1:End` with `End = INDEX(..)`; a table name that does not exist)
  that points at a stamp's sheet is an undecidable site (no guess) - only when a stamp
  candidate exists; it raises only when the verdict depends on it.
* A name whose `localSheetId` names no sheet raises only when a volatile name's use depends on
  it and no other mistake fails the file (see above).
* `NAME (` (whitespace before `(`) after a volatile function name: undecidable until Excel's
  reading is measured (question 11); the real fix belongs in `core/formula.py` (another
  agent's area), not here.
* Malformed formula text (policy: raises `FormulaError`/`GradingError`): because of the
  pre-filter, a malformed formula raises only when it mentions a volatile function name
  outside string literals (or, when a stamp exists, when it may reference the stamp's sheet).
  Elsewhere the check does not need its parse and does not raise.

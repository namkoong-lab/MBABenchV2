## Rule as implemented

A row fails only if it is **over 60 pt and more than twice as tall as its content needs**:
`height > MAX_ROW_HEIGHT_PT (60)` and `height > EXCESS_FACTOR (2) × need`.

Scope:
* Every worksheet, dialog sheet and macro sheet of the delivered workbook: hidden sheets, case
  tabs and the Instructions sheet included. There is no exemption and no starting-file diff.
* Hidden rows are ignored: `hidden="1"`, `ht=0`, or no `ht` on a `zeroHeight` sheet. This
  includes rows inside collapsed groups.

**Height.** A row's height is its stored `ht` **only when the row has `customHeight="1"`**; a
stored `ht` without `customHeight` is ignored, and so is a sheetFormatPr `defaultRowHeight`
without `customHeight="1"`: Excel auto-fits such rows to their content (measured by Patrick
2026-10-03: a non-custom 60 pt row and a non-custom 80 pt sheet default open at 15 pt;
`CUSTOM_HEIGHT_ONLY`; stats `non_custom_row_heights_ignored`,
`non_custom_default_heights_ignored`). A row without a custom `ht` takes the sheet's custom
`defaultRowHeight`; without that, one Normal-font line. Excel sizes rows without a
stored height to their content, so such rows never fail unless the sheet default is over the
cap. A sheet whose default row height is over 60 pt and more than twice one Normal line gets one
sheet-level mistake: every row without its own height, empty rows included, is that tall. Those
rows are covered by that one mistake and are not graded or listed again row by row (stats:
`default_height_rows_written`); rows with a height of their own on such a sheet are graded as
usual. (A sheet default over 60 pt that is NOT over twice one Normal line - only with a Normal
font over 23 pt - leaves its unsized rows as ordinary candidates.)

**Need of a row.** The largest need of its displayed cells. It is never less than one line of
the Normal font, because Excel sizes a row for the Normal font of its unformatted cells too. The
need of one cell is `lines × line height`:

* (2026-10-04) Sufficient column widths (69) reuses this line height and the wrap below for its
  cut-off wrapped text rule: `wrap_lines` takes an optional per-character width function for that
  (default: this check's table); this check's own results are unchanged.
* **Line height:** `LINE_HEIGHT_PER_PT (1.3) × font size`. The size is the cell font's size.
  For a rich-text string it is the largest size among its runs, since each run shows in its own
  font: a run without `<rPr>`, or whose `<rPr>` sets no size, has the cell's size; the cell font
  itself counts only for text outside the runs. The width factor is taken the same way.
* **Lines:**
  * 1 unless wrap is on. Wrap is on with `wrapText`, or with horizontal or vertical
    `justify` / `distributed`, which Excel also wraps.
  * With wrap on: a greedy word wrap of the text into the usable width. A word wider than a
    line breaks by characters. Typed line breaks start new lines, but only when wrap is on
    (`LINE_BREAKS_NEED_WRAP`).
  * Usable width: the column width (the `<col>` entry that applies, the later one winning where
    entries overlap: the core reader's one rule, `SheetHead.col_info`, shared with 69 and 70;
    question 12), or the summed width of a merge when the cell anchors one,
    converted to pixels with Excel's formula (ECMA-376 `col/@width`). That formula uses the
    Normal font's maximum digit width at 96 dpi, 7 px for Calibri 11, Aptos Narrow 11 and
    Arial 10. `CELL_MARGIN_PX` (5) is then taken off, and so is the alignment indent:
    ECMA-376 makes one indent level 3 spaces of the Normal font (`INDENT_SPACES_PER_LEVEL`),
    i.e. 9 px for Calibri 11 or Aptos Narrow 11 and 12 px for Arial 10 (space widths in
    `SPACE_EM`, measured from the font files by `scratch/rowscols/space_em.py`). It applies to
    left, right, general and distributed alignment (both sides for distributed).
  * Text width: the sum of per-character Helvetica/Arial advance widths (an AFM table in the
    code, stdlib only) × font size × the face's width factor (`FACE_WIDTH`). Each factor was
    measured once from the real font files (`scratch/rowscols/face_factors.py`). It is the
    wider of a prose sample and a capitals/digits sample, with bold measured separately.
    Examples: Arial 1.0, Calibri 0.918, Aptos Narrow 0.89, Verdana 1.149. Unknown faces such
    as Roboto are measured as Arial.
  * Numbers, booleans, errors and dates never wrap: 1 line.
* **Rotation:**
  * Rotated text (textRotation 1–180) needs its text width projected on the vertical:
    `width × sin(angle) + lines × line height × cos(angle)`.
  * Vertical stacked text (255) needs one line per character.
* **Merges:**
  * Covered (non-anchor) cells are ignored.
  * An anchor uses the merged width.
  * A merge spanning several rows is judged as **one block** (`MERGE_ROWS_WHOLE_BLOCK = True`,
    sanity Rec 73-6, applied 2026-10-04): the block's height is the sum of its visible rows'
    heights (hidden rows count 0), and each row is credited with the merge's need in proportion
    to its own height (`need × row / block`), so the row's ratio through the merge equals the
    block's ratio. A 48 pt title merged over rows of 40 + 62 pt is a 102 pt block for 62.4 pt
    of text (1.63×): row 6 passes. With the option off, the row gets the merge's need minus the
    other rows' heights (per-row share, the behaviour before 2026-10-04; that failed the same
    row 6 at 22.4 pt, 2.77×). The block changes only the need: the 60 pt cap stays per row, so
    a block of rows that are each ≤ 60 pt is never examined, however tall the block. The block
    share is never stricter than the per-row share (a row that fails with the block share fails
    with the per-row share too). When the anchor sits in a row that was not buffered (≤ 60 pt), it
    is read in a second pass, and only if the row is still undecided. Off-row anchors are always
    settled before any formula value is considered (review fix 73-F1).
* **Hidden columns:** cells in hidden or zero-width columns are not displayed and need nothing.

**Values.** A constant's text is read from the file. An unwrapped formula cell needs one line
of its font whatever its value, so its value is never read. A formula result's value can matter
only for a wrapped or rotated formula cell in a row over 60 pt that every value-independent cell
(off-row merge anchors included) leaves undecided. Such rows are settled in `finish()`:
1. With trusted values first. A trusted value never raises, so every row it settles is graded
   and listed (the mistake list stays complete).
2. If any row now fails (with or without values, or a sheet default fails), the verdict is fail
   and no untrusted value is needed (`UNTRUSTED_ONLY_IF_VERDICT_NEEDS = True`). Rows that only
   an untrusted value could settle are left undecided: listed in `stats.undecided_rows` (sheet,
   row, height, need without values, cells needing values), and the summary says how many.
3. Otherwise the first untrusted value that is really needed raises `GradingError` (no
   fallback).
With `UNTRUSTED_ONLY_IF_VERDICT_NEEDS = False`, an untrusted value raises even when the file
already fails, which was the behaviour before the review.

**Mistakes.** There is one mistake per run of consecutive failing rows, for example
`'Solution Model'!54:54` or `S!27:34`. The description gives:
* the height;
* the need and the deciding cell (e.g. `C54: 4 wrapped lines of 10 pt text`, or "one line of the
  11 pt Normal font");
* the ratio, with two decimals (`2.04x`, so a fail never reads `2.0x`);
* whether the height was set manually (`customHeight`), or (for a run mixing such rows with
  default-height rows) "stored or sheet-default height".

Stats per sheet give the rows over the cap, the failing rows with their need and ratio, and up to
20 tall rows that are justified, with the reason. They also give `formula_values_read`,
`second_pass_sheets`, `rows_undecided` / `undecided_rows` and the options in force.

**Buffering.** Cells of rows over 60 pt are buffered until `sheet_end`, because merges come after
`<sheetData>`. One-line cells (unwrapped, unrotated, or numbers) need only their column and font
size, so they are kept as compact column arrays per size; only wrapped or rotated text cells and
wrapped formula cells are kept whole, and only they count against `MAX_BUFFERED_CELLS`
(review fix 73-F5: 20,000 rows × 26 one-line cells at 80 pt now grade as a fail in 1.1 s).

## Edge-case decisions

* **Non-custom stored heights** (`ht` without `customHeight`, the cache Excel or LibreOffice
  writes) are ignored since 2026-10-03 (Excel auto-fits them); 1505 flips to pass.
* **Line breaks without wrap** give one line (`LINE_BREAKS_NEED_WRAP = True`). Excel shows a
  non-wrapped cell on one line.
* **Rotated text** needs its projected width. This is the content's need, not an exemption, so
  a rotated period header at 80 pt can pass.
* **Hidden sheets** are graded (whole workbook). **Cells in hidden columns** need nothing,
  because they are not displayed.
* **Vertical merges** (2026-10-04, sanity Rec 73-6): judged as one block; each row is credited
  with the merge's need × its height / the block's visible height, so the row's ratio equals the
  block's. Equal splitting would fail a 100 pt + 15 pt pair that holds 91 pt of text (45.5 a
  row); the proportional share gives 79 pt. The per-row share used until 2026-10-04 (need minus
  the other rows' heights) stays behind `MERGE_ROWS_WHOLE_BLOCK = False`. No corpus verdict
  depends on the choice (second review: 0 of 179 sanity fails name a merge in their deciding
  cell).
* **Formula results that are empty strings** need nothing when their value is read. An
  unwrapped formula cell counts as one line without reading.
* **Untrusted values only when the verdict needs them** (`UNTRUSTED_ONLY_IF_VERDICT_NEEDS =
  True`, sanity finding): the hard rule is that a check raises only when a value it really needs
  is unknown, and the decision is the file's pass/fail. A file that already fails does not need
  an untrusted value of a further row, so that row is left undecided (stats) instead of raising;
  its verdict cannot change. Trusted values are still read for every row that needs one, so
  that the mistake list stays complete (a first variant that read no value at all once the file
  failed dropped real mistakes from 25 GPT-6 files and attempt 1505, e.g. 14 `Tie_Keys` rows of
  2225, and was not kept).
* **Rich text** (review 73-F2): line height and width factor come from the runs that hold text;
  the cell font counts only for a run without its own size/face or for text outside the runs.
* **Indent** (review 73-F4) narrows the wrap width by 3 Normal-font spaces a level.
* **Normal font** = the font of the `Normal` cell style (builtinId 0), else `fonts[0]`.

## Known limits

* Text widths come from Helvetica/Arial metrics × a per-face factor. They are fractional, not
  rounded per glyph as Windows GDI does (±2 %).
* Faces outside `FACE_WIDTH` are measured as Arial; a very wide unknown face would be
  underestimated.
* Excel's wrap at hyphens is not modelled. Breaking only at spaces gives more lines, which is
  lenient.
* Number formats are not applied: a wrapped number is one line, and a rotated number is laid out
  as its raw digits.
* `MAX_BUFFERED_CELLS` (500,000 wrapped or rotated text cells in rows over 60 pt on one sheet)
  raises `GradingError`. One-line cells no longer count (73-F5). Nothing in the corpus comes
  close.
* The reader's run fonts do not carry `<rFont>` (the shared-string run's face name; the core's
  `parse_font` reads `<name>` only), so a rich run's face width is the cell's face. Sizes and
  bold are read. Not changed: it would be a core edit, and faces only scale the width estimate.
* The indent model (3 spaces of the Normal font, whole pixels) is ECMA's definition, not
  measured against Excel.
* With a LibreOffice value copy, the engine merges the copy for every formula cell of every
  sheet because 73 declares `needs_values` (sanity: attempt 4091, 17.5 MB with a 375 MB copy,
  66.7 s for 73 alone, 0 values read). In production 66 and 94 also declare `needs_values`, so the
  copy is streamed anyway; making the copy lazy is a core-engine design matter (deferred).
* Conditional formats that change font size do not exist in Excel (dxf fonts cannot set size),
  so they are ignored.

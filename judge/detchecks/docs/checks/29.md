## Rule as implemented

**Which names count.** Every `<definedName>` in workbook.xml that is **visible**
(`hidden` absent, `0` or `false`) and **not built-in**. Never counted:
* hidden names (`hidden="1"`), whatever their prefix or definition, broken ones included
  (toys T1/T2: hidden `solver_opt = Instructions!#REF!`);
* built-in names `_xlnm.*` (toy T1: `_xlnm.Print_Area` on the agent sheet);
* `BARE_BUILTIN_NAMES`: a **sheet-local** `Print_Area`, `Print_Titles` or `_FilterDatabase`
  written without the `_xlnm.` prefix (the ChatGPT writer does this; Excel's Name Manager
  shows built-ins under exactly these names). A workbook-level `Print_Area` still counts.

There is no prefix list: an add-in name (`RiskNumIterations`, `IQ_*`, `solver_*`) that is
visible counts like any other (toy T3). No starting-file diff: the whole delivered workbook
is graded.

**Fail** when any counted name is **unused** or **broken**. One mistake per name, at
`Name Manager: <name>` (`Name Manager: 'Sheet'!<name>` for a sheet-local name), in the
Name Manager's (file) order, severity major. The description quotes the definition and says
why (broken: what; unused: no consumer, or "only names that are themselves unused refer to
it (B, C)"; a name spelled like a cell, e.g. `Lim1`, gets a note that formulas writing it
point at cell LIM1).

**Used** = referenced by at least one consumer, directly or through other names:

| consumer | read from |
|---|---|
| cell formulas | every worksheet and macro sheet, every sheet state (hidden and very hidden too); normal, array and shared-master `<f>` texts. Shared children carry no text and use exactly the master's names (names are never shifted), so they add nothing |
| conditional formats | rule formulas and colour-scale / data-bar / icon-set thresholds (`cfvo val`, `<xm:f>`), main and x14 |
| data validations | `formula1` / `formula2`, main and x14 `<xm:f>` (toy T5) |
| charts | every `<*:f>` of chart parts reached through drawings (series, categories, titles, data-label ranges, chartex), chartsheets included |
| other drawings and controls | shape `textlink`; form controls (`xl/ctrlProps` `fmlaLink`/`fmlaRange`/`fmlaGroup`/`fmlaTxbx`; legacy VML `x:FmlaLink`/`FmlaRange`/...) |
| sparklines, tables | sparkline data/date ranges; table calculated-column and totals-row formulas |
| pivot caches | a worksheet source given by name (`worksheetSource name=`) |
| Excel objects | a slicer cache, timeline cache or query table whose `name` is the defined name (`Slicer_X`, `NativeTimeline_X`, `ExternalData_n`; Excel defines slicer names as `=#N/A`) |
| text references | `COUNT_TEXT_LITERAL_REFS`: a literal `INDIRECT("Rate")`, `INDIRECT("Ra"&"te")`, `INDIRECT("Sheet!Rate")`, `HYPERLINK("#Rate")`, `EVALUATE("Rate*2")` (in a name / macro sheet); also a run-time reference whose name part is fixed text, `INDIRECT("'"&A1&"'!Rate")`, when only one name can be meant (see "No guess"); `COUNT_HYPERLINK_LOCATIONS`: a cell hyperlink into the workbook whose location is the name (`<hyperlink location="Rate">`) |
| other names | Everything a **used** name (any kind, hidden too) references is used, so use passes through hidden helpers (`A1 = Helper`, hidden `Helper = Base*2` → Base used). `HIDDEN_AND_BUILTIN_NAMES_USE = True`: hidden and built-in names are also consumers on their own (e.g. `solver_adj = DecisionVar`, `_xlnm.Print_Area = PrintRng`); `False`: they pass use on only when something uses them. `TRANSITIVE_USE = True`: a name referenced only by unused counted names, only inside a cycle of them, or only by itself (recursive LAMBDA) is unused; `False`: any reference from another counted name counts |

How a formula "references" a name (core `formula.names_used_by`, Excel's rules): name
operands, both ends of `N1:N2`, `Name#`, `Sheet!Name`, `[0]!Name`, and calls `MyFn(...)` of a
non-built-in function (a LAMBDA name is used when called, toy T4). Never a use: an Excel
built-in called as a function (`YEAR(...)` is not the name `Year`), LET/LAMBDA parameters
(`_xlfn.LET(_xlpm.rate,...)`, `LET(x,1,x+1)`), another workbook's names (`[1]!Rate`),
string literals and text cells (a name mentioned in documentation is unused), cell
addresses (`Lim1` is cell LIM1). Names are matched as whole tokens, case-insensitively, so
`F_twostageTV` is not found inside `F_twostageTV_v1` (T4) and `Rate` not inside `RateHigh`.
Scope: on sheet S an unqualified `Rate` is S's local `Rate`, else the global one; `S!Rate`
is S's local, else global; a global name's definition resolves globally, a local name's with
its own sheet.

**Broken** (fails even when used):
* the definition contains `#REF!` outside string literals (`'4 - DCF'!#REF!`, `S!$B$2+#REF!`,
  `instructions!#ref!`) - toy T2;
* the definition is empty;
* `BROKEN_MISSING_SHEET`: it names a sheet the workbook does not have (`Missing!$A$1`;
  3-D refs check both ends; another workbook's refs and `Book.xlsx!Name` are not sheets).
* `BROKEN_ERROR_CONSTANT = False`: a definition that is only an error constant (`=#N/A`) is
  **not** broken (listed in `stats.error_constant_names_not_broken`); it must still be used.

**No guess** (raises `GradingError`), checked only when some counted name that is **not
broken** would otherwise be reported unused (a broken name fails whatever an unread consumer
might do, so its verdict never depends on the gates; its mistake text then says what was read
without claiming it is unused):
* the unused name is a macro name (`function` / `vbProcedure` / `xlm`);
* the workbook has a VBA project or XLM macro sheet (`Package.has_vba`), ActiveX controls
  (`xl/activeX/`), or Power Query (Mashup connection or `DataMashup` customXml) - consumers
  whose code this check does not read;
* a hidden or built-in name whose `localSheetId` names no sheet (scope unknown) and that
  is spelled like a visible name (it could shadow it), or whose definition refers to the
  unused name under some but not all possible scopes. Such a name is otherwise harmless: it
  is not counted, and a definition that resolves the same under every scope is used
  normally. A **visible** name with a bad `localSheetId` always raises (it cannot be resolved).
* `DYNAMIC_TEXT_GATE`: a run-time text reference (`INDIRECT` / `EVALUATE` / `HYPERLINK` whose
  first argument is not plain literal text) **can produce the unused name's spelling**. This
  is decided from the **shape of the argument only**, never from what other cells hold. The
  argument is split at top-level `&` into string literals and computed pieces (cell refs,
  functions...); `ADDRESS(r,c)` with absolute A1 output (`abs_num` 1-3 or omitted, `a1`
  TRUE/omitted) or with a sheet argument counts as a cell address. The **name part** of a
  reference is the text after its last `!` (names never contain `!`):
  - fixed name part that is a cell, range or no reference (`"'"&A1&"'!B5"`,
    `"Data"&n&"!B5"`, `ADDRESS(1,2)`, `A1&"!$C$3:$D$9"`) → can name nothing, ignored;
  - fixed name part that spells a name (`"'"&A1&"'!Rate"`) → uses that name on the computed
    sheet: **used** when every sheet resolves it to the same name (`COUNT_TEXT_LITERAL_REFS`),
    else raise if one of the candidates looks unused;
  - computed name part → a pattern: `"Rate_"&B1` can produce only names starting `Rate_`;
    `"'Data'!B"&n` only names starting `B`; `A1&"_old"` only names ending `_old`;
    `INDIRECT(A1)` (also when A1 holds a helper formula `="Rate_"&B1`) and computed `EVALUATE`
    text can produce **any** name. A computed piece may hold a whole sheet qualifier (so
    `"Rate_"&B1` can produce any name if a sheet name starts with `Rate_`), but is assumed
    not to add range / union / intersection operators;
  - `HYPERLINK` reaches a name only through `#...` (or `[book]...`) text: a literal start
    without `#` (`"https://..."&A1`) is a web/file link and ignored; a computed start
    (`HYPERLINK(B1)`) counts only when some text constant or string literal in the workbook
    starts with `#` or `[`.
  Names spelled like cells (`Lim1`) are never produced (the text is the cell).
* a **hidden or built-in name whose definition cannot be parsed** (`Helper = Rate+(`) and
  that spells the unused name: it may be the name's only user, so the check raises (the
  message quotes the parse error). Such a definition is parsed only when it spells a relevant
  name or mentions INDIRECT/EVALUATE/HYPERLINK; when it does and cannot be parsed, it gets a
  "maybe" edge to every name it spells (and, if it mentions one of those functions, an
  any-name pattern). The maybe edge is live when the hidden name is a consumer
  (`HIDDEN_AND_BUILTIN_NAMES_USE`) or is itself used; a counted name that ends up used by
  anything else is unaffected (`Rate` used by `S!A1` → pass).
* malformed formula text (unbalanced parentheses...) raises `FormulaError` at once for every
  **counted** name's definition (broken or not cannot be told) and for consumer texts the
  check needs to parse (texts spelling a remaining candidate name or a name leading to one,
  or calling INDIRECT/EVALUATE/HYPERLINK).

**How it runs.** All workbook-level consumers (names graph, charts, drawings, controls,
tables, pivots, slicers) are read in `start()`. Cells are streamed only while some counted
name is still unproven; once every counted name is used, the remaining sheets are not
opened (toy T6 Pass: 96 formula texts scanned out of 611k). Formula texts are pre-filtered:
the lower-cased text is split into identifier runs (the characters Excel allows in a name),
and the text is parsed only when a run equals a remaining candidate spelling (or the
spelling of a not-yet-used name leading to one) or the text contains
`indirect|hyperlink|evaluate`. A run starting with Excel's function-storage prefixes
(`_xlfn.` `_xlws.` `_xll.` `_xludf.` `_xleta.`) is also looked up with them stripped, because
a call stored as `_xludf.Rate(1)` / `_xll.Rate(1)` is a reference to the name `Rate` (core
rule, docs/formula.md; second-review fix). A name token is always a whole run, so this
misses nothing, and its cost does not grow with the number of names (review finding: the old
one-regex-per-name alternation took 333 s on T6 with 400 unused names). Name definitions are
parsed only when they spell a name from which a counted name is reachable (fixed point); an
uncounted definition that then fails to parse becomes a "maybe" user of the names it spells
(see "No guess"), so it raises only when one of them would otherwise be called unused. No
cell values are read (no provenance dependence).

## Edge-case decisions

* Usage is per name token, never per target cell (T1 Tax_rate_v1).
* A name used only by another unused visible name is unused (`TRANSITIVE_USE = True`);
  both are listed. The toys have no name-to-name reference, so this follows the rubric
  ("current, actively referenced"; "orphaned ... entries should be removed") and report §3.
* Hidden and built-in names are consumers (`HIDDEN_AND_BUILTIN_NAMES_USE = True`): Excel /
  add-ins read them (Solver's `solver_adj`, print areas), and this check cannot tell an
  add-in's hidden name from an agent's. With the switch off, use still flows through a
  hidden or built-in name that something uses (fixed 2026-10-03; it used to stop there).
* Literal INDIRECT/HYPERLINK/EVALUATE text and hyperlink locations count as use (no toy has
  one): Excel resolves the name when evaluating/following them. A run-time reference whose
  name part is fixed (`"'"&A1&"'!Rate"`) counts too, when every sheet resolves it to the
  same name.
* Run-time references are judged by the shape of their argument only (see "No guess"):
  provably cell-shaped ones never block grading; ones that can produce any name
  (`INDIRECT(A1)`) raise whenever some name looks unused. Values of other cells are never
  read to narrow this down (no value reads, no provenance dependence).
* A hidden / built-in name with a bad `localSheetId` raises only when it can matter (same
  spelling as a visible name, or its definition resolves differently per scope and the
  target looks unused); before 2026-10-03 every such name raised.
* A broken name is one mistake even if it is also unused (both reasons in the text).
* Duplicate entries with the same name and scope: only the first is ever resolved, so the
  second is reported unused.

## Known limits

* Consumers outside the readable XML raise instead of grading (VBA, ActiveX, Power Query,
  macro names); names used from other workbooks are not visible at all.
* Run-time references: a computed piece is assumed not to add range / union / intersection
  operators (`"'Data'!B"&n` with n = `"1:Rate"` would reach `Rate`); a `HYPERLINK` whose
  computed start gets its `#` from `CHAR(35)` rather than from a text is not seen. Any name
  part that is computed with no fixed prefix/suffix (`INDIRECT(A1)`, helper cells) makes the
  check raise rather than grade when a name looks unused.
* A chart series qualified with the workbook's own file name (`Model.xlsx!Rng`, the form
  older Excel versions wrote) reads as another workbook's name (modern Excel writes `[0]!Rng`
  or `Sheet!Rng`; the delivered file name is not a reliable key). Reproduced by the second
  review (probe P32); question 10.
* Not read: pivot-table calculated fields, data-table input cells (cell refs anyway),
  ActiveX `linkedCell` in sheet XML, linked pictures.

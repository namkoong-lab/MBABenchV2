# 100 Potential Dangers/Automatic calculation mode

Code: `detchecks/checks/c100.py`. Tests: `detchecks/tests/test_checks_100.py` (10 tests). Built
2026-10-28 for judge v15 (Patrick's hierarchy of the same day; `V3_DETCHECKS_TODO.md`). No core change;
no LibreOffice run (`needs_values = False`). The check uses the `undecided` outcome of judge v15
(`checks/base.py`, `utils/det_checks.py`): the LLM judge decides one case, told why.

Rubric: "The workbook should be delivered with calculation set to automatic - and, where intentional
circularity requires it, with iterative calculation enabled and that requirement stated. Manual
calculation mode means displayed values may not reflect the inputs currently shown." Bad: "saved in
manual calculation mode without disclosure ... or iterative calculation is required but not
enabled." House rules v3: "Circularity only where the economics require it, each instance noted and
fitted with a breaker switch, with iterative calculation enabled and stated."

## Rule as implemented (Patrick 2026-10-28)

Evaluated in order; the first rule that fires decides:

| rule | condition | verdict |
|---|---|---|
| 1 | `<calcPr calcMode="manual">` | **fail** by code, location `workbook` ("calculation mode is manual"); the rubric's "without disclosure" is ignored - manual always fails |
| 2 | build the formula dependency graph, search for cycles | - |
| 3 | no cycle | **pass** by code (iteration on or off; `iteration_on_without_cycle` in stats) |
| 4 | a cycle, iterative calculation off (`iterate` absent / 0) | **fail** by code, one mistake per cycle: "circular reference through N cell(s) (...); iterative calculation is off" |
| 5 | a cycle, iteration on | **undecided**: the LLM is asked whether the workbook states that the model is intentionally circular, where, and that iterative calculation is required (cover, notes, legend, comments); pass only if it does |
| 6 | anything else | fail - the LLM's call under rule 5; a breaker switch alone excuses nothing (switch AND iteration AND statement) |

Settings come from `xl/workbook.xml` `<calcPr>` (`Package.calc_pr`): `calcMode` auto (default) |
manual | autoNoTable (= automatic); `iterate` "1" / "true" = on; `iterateCount`, `iterateDelta`
reported. No `<calcPr>` = automatic, iteration off.

## The graph

- **Nodes**: every formula cell of every worksheet and macro sheet (hidden too) - normal, shared
  master and child (the master's references shifted by the child's offset, as `formula.shift`
  does), array / spill anchors; a written non-anchor member of an array range depends on its anchor;
  a reference into an array range (unwritten members included) reaches the anchor. Every defined name
  with a readable scope and a formula definition. Table calculated columns need no node of their own:
  Excel writes each cell's formula into the sheet.
- **Edges**: a formula → each cell, range, spill reference (`A1#` → anchor), structured reference
  (resolved to the table's rows and columns; `[#This Row]` / `[@Col]` to the formula's row;
  `[#Headers]`, `[#Totals]`, `[#All]`, `[Col1]:[Col2]`) and defined name it reads (name operands and
  `MyLambda(...)` calls); a 3-D reference `Jan:Dec!B5` reaches every sheet of the span. A reference to
  a constant cell, an external workbook, `#REF!`, R1C1 text or a missing sheet leads nowhere.
- **Range nodes**: a range is never expanded into cells up front. A range node leads to the formula
  cells inside it, found with a per-sheet column index (sorted rows per column, bisect), after cutting
  the rows along the dyadic blocks of a segment tree over 1..2^20 (`dyadic_blocks`): a block of more
  than 64 rows that holds more than 48 formula cells splits into its two halves, so the cumulative
  family `=SUM($B$1:B5)`, `=SUM($B$1:B6)`, ... shares its blocks (test: 6,000 formulas, ~210k
  successor steps, 0.13 s) instead of enumerating n²/2 cells.
- **Static means static**: a cycle through an `IF` branch that is never both active still counts
  (consistent with the house rules' iteration requirement even with a breaker switch OFF).
- **What-if data tables** (`<f t="dataTable">`): constants, no edges.
- **Dynamic references**: INDIRECT / OFFSET build references the graph cannot see; the miss is
  accepted and recorded (`stats.dynamic_refs`: count, examples). Such files already fail Avoid
  volatile functions (80).
- **Workbook-scoped names with unqualified references** (`=A1*2` as a global name: relative to the
  active sheet in Excel) are skipped and counted; a sheet-local name's unqualified references are on
  its sheet. Names with an unknown scope (bad `localSheetId`) are left out and counted.
- **Geometry and reference-returning functions** (sanity run, 2026-10-28): a reference inside ROWS /
  COLUMNS / ROW / COLUMN / AREAS / SHEET / SHEETS / ISREF / FORMULATEXT / ISFORMULA is never
  dereferenced by Excel, and only a computed part of an INDEX / OFFSET base reference is read, so these
  create no edge (`GEOMETRY_FUNCS`, `REFERENCE_ARG_FUNCS`; counted in `geometry_refs_skipped` and
  `dynamic_refs.index_offset_reference_args`). Evidence: attempt 2539 (Excel Online, iteration off)
  caches 1, 2, 3 for `=IF(ROWS($B$14:B14)<=$C$8,ROWS($B$14:B14),"")` in B14:B16; the first cut flagged
  340 such counters there and 364 in attempt 1924 as self-loops. The cost: a cycle that runs only
  through an INDEX / OFFSET result is missed (accepted, as for INDIRECT).
- **Fast path** (`_fast_entries`, `FAST_PATH`): the parser costs ~50 us per distinct text and the
  largest attempts hold 1-1.5 million distinct texts (claudecode writes no shared formulas), so plain
  formulas - direct A1 references, numbers, strings, operators, calls of known Excel functions, INDEX /
  OFFSET / INDIRECT included - are read with one regex pass that yields exactly the parser path's
  entries and counters; anything else (a name, a table, `#`, `@`, an error literal, an array constant,
  R1C1, a 3-D span, a trimmed range, the intersection operator, an unknown function, a book) goes to the
  parser. Checked against the parser on every form the unit test lists and on 5.5 million distinct real
  texts from eight sanity-run attempts (93-100 % taken by the fast path, 0 mismatches).
- **Cycles**: Tarjan's strongly connected components, iterative, successors enumerated lazily; a
  cycle is a component of more than one node or a self-loop (`=A1+1` in A1, `=SUM(A1:A10)` in A5,
  `=SUM(A:A)` in column A). Reported by its cells grouped into rectangles per sheet (12 per sheet
  quoted), smallest cycle first; a cycle through names only is located at `Name Manager`. A walk
  of more than 50,000,000 successor steps raises `GradingError` (no fallback; none seen).

## Verdicts and the LLM note

Rule 4 mistake: `Calc!B1:B2`: "circular reference through 3 cell(s) (Calc!B1:B2, Inputs!C3);
iterative calculation is off (calcPr iterate not set), so Excel cannot resolve it: enable iterative
calculation and state the requirement on the cover, or break the loop." Rule 5 `llm_note`
(`C100.LLM_QUESTION`): "The deterministic grader found a circular reference through these cells:
cycle 1 (3 cell(s)): Calc!B1:B2; Inputs!C3. Iterative calculation is enabled (calcMode=auto,
iterate=on, iterateCount=100, iterateDelta=0.001). Does the workbook state that the model is
intentionally circular, where the circularity is, and that iterative calculation is required (cover
sheet, notes, legend or comments)? Pass only if it does; a breaker switch alone is not a statement."
The judge note in `rubric_9_guidance.yaml` tells the LLM that with such a note the only question is
disclosure, and how to grade without one.
